# 採点者への指示書（コメント取得戦略の実験）

あなたは、TikTok の楽曲の拡散を分析したレポートを採点する。同じ曲について、いくつかの版のレポートがあり、
あなたが採点するのはそのうちの1本（`report.md`）。どの版がどういう条件で作られたかは知らされない。推測もしない。

**読んでよいのは、渡された束のフォルダの中のファイルだけ**（`report.md`・`claims.json`・`items.md`・`article.md`）。
リポジトリのほかのファイル・ほかの束・ほかの版のレポートを開かない、検索もしない。
採点の結果は、指定されたファイル（`grade.json`）に書く。

## 束の中身

| ファイル | 中身 |
|---|---|
| `report.md` | 採点するレポート。本文に根拠として「seq N（動画の番号）」「cid（コメントの番号）」が付いている。付録は外してある |
| `claims.json` | **参照の主張**。同じ曲の別の版のレポートの構成案から取り出した主張。いくつかの組（`R1`・`R2`…）に分かれている。組ごとに別の版から取った |
| `items.md` | 著者（人間の専門家）の記事の主張を項目に割った表 |
| `article.md` | 著者の記事の本文（正解として使う） |

## 採点すること

### 1. 参照の主張の再現（いちばん大事）

`claims.json` の主張を1つずつ、`report.md` がその主張を**立てているか**判定する。言い回しが違っても、同じ中身を同じ向きで主張していれば「立つ」。

| 判定 | 基準 |
|---|---|
| `立つ` | 同じ中身を主張している。根拠（動画・コメント・数字）は違ってもよい |
| `弱い` | 一部だけ、触れているが主張になっていない、条件や範囲が大きく違う |
| `無い` | 触れていない |
| `逆` | 反対のことを主張している |

- 判定ごとに、`report.md` の該当の一文をそのまま引く（`無い` なら空）。引けないのに `立つ` にしない
- 主張の中の細かい数字の違い（再生数の丸め方など）では落とさない。主張の**向きと中身**で見る
- `guess: true` の主張は、レポート側が推測として書いていても `立つ` でよい
- 組の間で同じような主張が重なっていても、組ごとに独立に判定する

### 2. 記事の主張の表（`items.md`）

各項目を、`report.md` が独立に述べているかで判定する: `○` 述べている／`△` 一部・弱い／`×` 述べていない・違う。理由を1〜2文で。

### 3. 8観点のうち3つ（1〜5点）

| 観点 | 何を見るか | 5 の基準 | 1 の基準 |
|---|---|---|---|
| D 「なぜ」の深さ | 記事の理由づけ（作品・世代・界隈の価値基準・フォーマットの性質など）に対し、データから言える範囲でどこまで迫るか。言えないことを言えないと書いているか | 記事と同等の理由を、データの根拠付きで示している | 一般論のみ |
| E 結果・再現性 | TikTok の外への波及や、再現できる要素を、データの範囲で扱えているか | データで言える結果を述べ、外は明示的に留保 | 空欄、または根拠のない断定 |
| G 新規価値 | 記事に無い発見（データでしか見えないこと）があるか | 3つ以上、根拠付き | なし |

点ごとに、根拠（記事とレポートの記述）を2〜3文で書く。3・4点も使ってよい。

### 4. 参照に無い主張

`report.md` の大きな主張のうち、`claims.json` のどの組にも無いものを、最大5つ書き出す（主張の要約と、レポートが添えた seq・cid）。

### 5. 総合

「この曲を知らない読者が、記事の代わりにこのレポートを読んで、同じ結論に達するか」を一文で。

## 出力（`grade.json`）

```json
{
  "claims": {
    "R1": [{"id": "R1-01", "verdict": "立つ", "quote": "report.md の一文"}, ...],
    "R2": [...]
  },
  "items": [{"id": "S1", "verdict": "○", "why": "..."}, ...],
  "D": {"score": 4, "why": "..."},
  "E": {"score": 3, "why": "..."},
  "G": {"score": 4, "why": "..."},
  "only_here": [{"claim": "...", "evidence": "seq 12, cid 7534..."}],
  "overall": "一文"
}
```

- `claims` は `claims.json` の全部の主張について、id の順に全部書く（抜けがあると集計できない）
- JSON として読める形で書く（書いたら `python3 -c "import json;json.load(open('grade.json'))"` で確かめる）
- 最後の返事は「書いた」と、`立つ`・`弱い`・`無い`・`逆` の数だけでよい。採点の中身を返事に書き写さない
