# 課題: TikTok 楽曲 UGC の分類軸の提案とラベル付け（答えを見ない試験）

あなたは TikTok の楽曲バズ分析の下ごしらえを担当する。対象楽曲は **KANA-BOON「シルエット」**（NARUTO 疾風伝 OP。2025年7月〜12月に TikTok で再バズした）。
この作業は「人間の分析者が書いたレポートを、データからどこまで復元できるか」の**試験**である。したがって:

## 絶対に守ること（試験の条件）

1. **この楽曲のバズについて Web 検索・Web 取得をしない。** note / X / ニュース等で「シルエット TikTok」を調べるのは禁止。
2. **`output/trial_silhouette/_contaminated/` の中身を読まない。** ここには答え（先行の分類結果）が入っている。
3. 参照してよい過去レポートは、**別の楽曲**の次の2本だけ（分析の枠組み・語彙・レポートの体裁を学ぶため）:
   - https://note.com/keitarocomp/n/n06c909376d1b （こっちのけんと「はいよろこんで」）
   - https://note.com/keitarocomp/n/nf643834b934f （「一目惚れ」）
4. **データを見る前に**、この楽曲の TikTok でのバズについて自分の事前知識で知っていることを `clean/prior_knowledge.md` に書き出す（知らなければ「知らない」と書く）。何を知っていたかで結果の解釈が変わるので正直に。

## 入力（すべて `output/trial_silhouette/llm_input/`）

- `taxonomy_sample.md` … 分類軸を考えるための層化サンプル（再生上位100 + 最初期40 + 離陸後の各週から無作為6）。各動画に、投稿者の属性（フォロワー数・bio・認証）、投稿地域、本文言語、TikTok が付けたカテゴリラベル、説明文、ハッシュタグ、画面上の文字、エフェクト、TikTok の提案語（検索・コメント由来）が付いている
- `label_set.md` … ラベル付け対象 200本（離陸前は全件80 + 離陸後の上位70 + 無作為50）
- `sheets/sheet_NN.jpg` … サムネイルの一覧画像（各枠の上に `seq N` と書いてある）。`sheets/index.json` が seq → シート名の対応。**必ず全シートを見ること**（説明文が空でもサムネイルで判断できる場合が多い）
- `records.jsonl` … 全880本の圧縮レコード（週次の流れを見たいときに使う）。`../weekly.tsv` に週次の本数と再生数

「属性取得なし」とある動画は、削除済み等でページから属性が取れなかったもの。CSV 由来の説明文と数値だけで判断する。

## 出力（`output/trial_silhouette/clean/` に書く）

### 1. `taxonomy.json`
過去レポートの枠組み（誰が＝界隈、どう使ったか＝フォーマット、なぜこの曲か＝採用文脈、拡散段階）を参考に、**この楽曲のデータに合った**分類軸を提案する。軸の名前は次の5つに固定し、値（カテゴリ）はあなたが決める:

```json
{
  "community": {"<key>": "<定義と見分けるシグナル>", ...},   // 界隈: 投稿者はどの集団か
  "format":    {"<key>": "<定義>", ...},                     // 何をした投稿か
  "motive":    {"<key>": "<定義と手掛かりになる語>", ...},   // なぜこの曲を使ったと読めるか
  "region":    ["JP", "...", "unknown"],                     // 地域コード
  "tier":      ["official_artist", "official_brand", "large_creator", "general", "unknown"]  // アカウント種別
}
```
各軸に必ず `unknown` を入れる。カテゴリは多すぎない（community は 8〜14 程度）。

### 2. `labels.tsv`
200本すべてにラベルを付ける。タブ区切り、ヘッダ付き:
```
seq	community	format	motive	region	tier	conf	reason
```
- `conf` は H / M / L（H = 複数のシグナルが一致、M = 1つのシグナル、L = 推測）
- `reason` は日本語で1行（根拠にしたシグナルを書く。例: 「bio に『Utatane所属 16歳』、#今日好き」）
- サムネイルを根拠にした場合は reason に「サムネ:」と書く

### 3. `pathway.md`
ラベルと `records.jsonl` / `weekly.tsv` から読み取れる**拡散経路**を、過去レポートの「UGC の拡大経路」の章と同じ体裁で書く（イノベーター → アーリーアダプター → アーリーマジョリティ、または時系列の段階分け）。各段階に **代表動画を2〜3本**（seq・日付・投稿者・再生数・なぜ代表か）を挙げる。**推測と観測を分けて書く**。データから言えないことは言えないと書く。最後に「再生数の多い順に切った場合に落ちるが、動線上は重要な動画」を挙げる。

## 進め方

1. `prior_knowledge.md` を書く（最初に）
2. 過去レポート2本を読んで、分析の枠組みと語彙を把握する
3. `taxonomy_sample.md` と全シートを読み、`taxonomy.json` を書く
4. `label_set.md` を読み、200本にラベルを付ける（サムネイルは `sheets/index.json` で引く）
5. `pathway.md` を書く
6. 最後に、作業で困ったこと・データに足りなかった属性・迷った境界を `notes.md` に書く

出力ファイルはすべて UTF-8。完了したら、各ファイルのパスと、ラベルの conf の内訳（H/M/L の本数）を報告する。
