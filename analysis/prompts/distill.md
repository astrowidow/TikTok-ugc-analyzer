# 課題: 過去レポート群から「分析の言語」を蒸留する（層1 知識ベースの部品づくり）

著者（山本慶太朗 / keitarocomp、Hi-Trink Inc.）が note に書いた TikTok/YouTube 楽曲バズ分析の記事群がある。
これから同じ著者の枠組みで**新しい楽曲の分析レポートを AI が書く**ために、記事群に埋め込まれた
**概念・語彙・分析の型・文体**を、後で参照できる形に抽出する。あなたは割り当てられた記事だけを読み、部品を書く。

## 入力

- 記事本文: `/Users/belle/workspace/TikTok-ugc-analyzer/output/notes_corpus/<file>.md`（割り当てファイルは呼び出し時に渡される）
- 一覧: `/Users/belle/workspace/TikTok-ugc-analyzer/output/notes_corpus/INDEX.json`（title, date, url, kind の参考）

割り当て以外の記事は読まない。Web 検索・取得もしない（記事本文が唯一の情報源）。

## 出力（`/Users/belle/workspace/TikTok-ugc-analyzer/output/notes_corpus/distilled/part<N>/`）

### 1. `cards.jsonl` — 記事1本につき1行
```json
{"file": "...", "title": "...", "date": "YYYY-MM-DD", "kind": "楽曲分析|流行曲Report|講座|コラム|その他",
 "song": "曲名", "artist": "アーティスト", "platform": "TikTok|YouTube|両方",
 "buzz_type": "著者の分類語をそのまま（例: 『TikTok内で使用数が多かった曲』『リバイバル型』など。無ければ null）",
 "pathway": "拡散経路の要約（3行以内。誰が起点→どこへ→どう広がった）",
 "communities": ["記事に出てくる界隈・層の名前をそのまま"],
 "formats": ["UGC のフォーマット名をそのまま（例: 推し動画, 踊ってみた, 心理テスト）"],
 "why_claims": ["著者が『なぜバズったか』として挙げた理由を短く。3〜6件"],
 "reproducible": ["『再現性のある要素』の章の要点。無ければ空"],
 "evidence_style": "根拠の示し方（例: 再生数・投稿日を並記 / コメント引用 / Chartmetric / VidIQ）",
 "coined_terms": ["著者独自の言い回し・造語（例: フィルター機能, UGC自己増殖フェーズ）"],
 "numbers": {"ugc_count": "記事中の UGC 数などの主要数値。無ければ空"},
 "reusable_insight": "他の楽曲の分析に転用できる一般化された知見を1〜2文"}
```

### 2. `glossary.md` — 概念辞書（部品）
記事群で**繰り返し使われる、または定義されている**概念・語彙を、`## 用語` → 定義（著者の言葉に忠実に）→ 初出/根拠の記事 → 使われ方の例、の形で。
対象: 界隈の名前とその特徴、フォーマットの語彙、採用文脈・動機の型、バズの分類（教科書の分類名が出てきたら必ず）、拡散段階の語彙
（イノベーター等の使い方）、楽曲構造の語彙（Riser、ブレイク、切り出し箇所…）、SNS 指標の読み方、繰り返し出る因果パターン。
**著者が否定・批判している通説**（例:「TikTok＝ダンス」）も「否定された通説」として載せる。

### 3. `style.md` — 文体・体裁の観察
章立ての型（節の名前と順序）、冒頭の書き出し、数値・日付・動画の引用の仕方、断定の強さ、一文の長さ、
「【山本の気づき】」のような定型パーツ、締めの書き方。実例を短く引用して示す。

### 4. `summary.md` — この部の所感
この部の記事群で目立った分析の癖・進化（初期と後期の違い）・他の部と統合する際の注意。

## 進め方
1. 割り当て記事を日付順に読む（1本読むごとに cards.jsonl に1行追記する。全部読んでからまとめて書かない）
2. 読み終えたら glossary.md → style.md → summary.md
3. 完了したら、読んだ本数・cards の行数・glossary の用語数を報告する。聞き返さず自分で決めて進める
