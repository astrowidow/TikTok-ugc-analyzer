# 課題: 4部に分かれた蒸留結果を、1つの「層1 知識ベース」に統合する

入力: `/Users/belle/workspace/TikTok-ugc-analyzer/output/notes_corpus/distilled/part1〜part4/` の各 `cards.jsonl` / `glossary.md` / `style.md` / `summary.md`
（著者 山本慶太朗の note 記事 82本を、時期順の4部に分けて別々の担当が抽出したもの。担当間で用語の重複・表記揺れ・定義の差がある）

出力: `/Users/belle/workspace/TikTok-ugc-analyzer/output/notes_corpus/distilled/` 直下に次の4つ。
**この知識ベースは、新しい楽曲の分析レポートを AI が書くときに毎回まるごとプロンプトに入れる。** だから**サイズ上限を厳守**し、重複を畳み、記事本文の再録はしない。

## 1. `GLOSSARY.md`（上限 40,000 字）
- 4部の glossary を統合。**同じ概念は1項目に**（表記揺れは「別表記:」として併記。例: 楽曲使用数＝UGC数、アーリーイノベーター→アーリーアダプターの誤記）
- 章立て: A 著者の分析の型（固定順序と各段の問い）／B バズの定義と分類（教科書の十四分類は**14個すべて**、番号・名称・一言定義・表記揺れ）／C 拡散段階（イノベーター理論の使い方、段階の切り方の基準）／D 界隈（名前・特徴・見分け方。記事で実際に使われた名前を優先）／E フォーマット（UGC の型の語彙）／F 採用文脈・動機（なぜその曲か、の型）／G 楽曲構造と切り出し箇所／H SNS 指標の読み方と「意味のあるバズ」／I 因果パターン（繰り返し出る「〜だから〜」）／J 否定された通説
- 各項目: `**用語**（別表記）— 定義（著者の言葉に忠実に、1〜3文）｜初出・根拠: 記事名（日付）｜使われ方の例（1つ）`
- 定義が部ごとに違う場合は「初期の定義→後期の定義」と**時期の変化**として書く（後期を現在地とする）

## 2. `STYLE_GUIDE.md`（上限 12,000 字）
- 楽曲分析レポート（TikTok 版）の章立ての標準形（節名と順序、各節に書くこと）。YouTube 版・月次 Report・講座は簡潔に別記
- 冒頭の書き出し、動画・数値・日付の引用の型、断定とヘッジの語彙（三段階）、定型パーツ（【山本の気づき】等）、締め方
- **後期（2025年後半以降）のトーン**を標準とする（バズ特化から「楽曲が役割を持つか・余白・キャッシュポイント・ブランディング一貫性」の診断へ）。初期との差は一段落で
- ライター別の文体差（スイ／宮本／Cosmey）は短く注記。生成時は著者本人の文体に揃える

## 3. `cards.jsonl`（82行、1行 600 字以内）
- 4部の cards を日付順に連結し、各行を圧縮する（キーは維持: file, title, date, kind, song, artist, platform, buzz_type, pathway, communities, formats, why_claims, reproducible, coined_terms, reusable_insight。`evidence_style` `numbers` は短く）
- 同じ曲が複数号に出る場合は `related` キーで相互参照

## 4. `README.md`（上限 4,000 字）
- この知識ベースの使い方（新規レポート生成時に 1・2 を全文投入、3 から近い過去レポートを 5〜8 本選んで全文を層2として投入）
- 統合時に見つかった注意（用語揺れ、誤記、有料記事の欠落、同一曲の再登場、担当間の定義差）
- 各部の summary.md の要点を統合した「著者の分析の進化」（3〜5行）

## 進め方
1. 4部の summary.md を先に読む（統合の注意が書いてある）
2. glossary 4本を読み、A〜J に振り分けながら統合 → GLOSSARY.md
3. style 4本 → STYLE_GUIDE.md
4. cards 4本 → cards.jsonl（JSON の妥当性を検証）
5. README.md
6. 各ファイルの文字数を数えて上限内であることを確認し、報告する（用語数・カード行数・文字数）。上限を超えたら削って再確認。聞き返さず進める
