# 利用者の AI をどうつなぐか — 使い勝手の具体（2026-09-30、検討中）

> **追記（同日）**: ユーザーの反応は「微妙。サービス側から利用者の AI に仕事を投げる形にできないか」「**Claude と ChatGPT の両対応は必須**」。
> 投げる形の調査結果は第6章。第2〜5章は「AI が取りに来る形」の検討として残す。

前提（ユーザー、2026-09-30）: 利用者は友達3人、マーケターで理解は早いが IT リテラシーはほぼゼロ。
「自分の AI アカウントにログインするだけ」「Claude か ChatGPT かを選ぶだけ」が理想。インストールはさせてよいが、細かい設定は利用者にはできない。

**この文書の中身は、各社の公式ヘルプを読んだ段階のもの。実機ではまだ試していない**（第5章で先に試す）。

---

## 1. 動かせない制約

- **サービスが利用者の Claude のログインを預かって代わりに使うことはできない。** Anthropic は、承認なしに第三者のサービスが claude.ai のログイン（定額プランの枠）を使わせることを認めていない（[Agent SDK の説明](https://code.claude.com/docs/en/agent-sdk/overview)）。
  だから **AI は利用者の Claude・ChatGPT のアプリの中で動き、サービスはそこに「道具」としてつながる**形しか取れない
- AI の仕事の数が多い。1回の分析で、ラベル付け数回〜十数回、コメント分析は動画1本ずつで数十〜240回、執筆は章ごとに約8回。
  **チャットに利用者が1回ずつ頼む形では回らない。** AI が仕事を自分で取りに行き、続けて片付ける形が要る

## 2. Claude を選んだ人の使い勝手（有力）

Claude のデスクトップアプリには **Cowork** がある。ターミナル不要で、Claude Code と同じ仕組みで長い作業を自分で進める、コードを書かない人向けのモード（[Cowork の説明](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)）。Pro 以上。
さらに Cowork には**定期実行**があり、毎時・毎日などで決まった依頼を繰り返せる。**PC が閉じていても Anthropic 側で動く**（[定期実行の説明](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork)）。

### 最初の1回だけ（運営が一緒にやる。15分ほど）

1. Claude の Pro 以上を契約し、[Claude デスクトップアプリ](https://claude.com/download)を入れてログイン
2. 「カスタマイズ → コネクタ → ＋」で、名前「UGC分析」と、**運営から渡されたその人専用の URL** を貼って追加（[コネクタの追加](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)）
3. Cowork の「予定 → 新しいタスク」で、頻度「毎時」、依頼文に運営が用意した1文（例:「UGC分析に仕事があれば、全部片付けて」）を貼る

これで設定は終わり。以後、利用者が Claude を開く必要は基本的にない。

### 分析のたびの流れ（利用者が触るのはサービスの画面だけ）

| 時刻の目安 | サービス | Claude（毎時の定期実行） | 利用者 |
|---|---|---|---|
| 0:00 | | | ブラウザでサービスを開き、ログインして楽曲名を入れ「開始」。画面を閉じてよい |
| 0:00〜1:30 | 動画一覧・属性・サムネを取る | | |
| 〜2:30 | 「AI の番」 | 次の毎時の実行で仕事に気づき、**分類の軸の案**を作って返す | |
| 任意 | 「確認の番」 | | 画面で軸の案を読み、直して上げる（または「案のまま確定」） |
| 〜+1h | 「AI の番」 | ラベル付け、段階の案 | |
| 任意 | 「確認の番」 | | 段階の案を確認 |
| 〜+数時間 | 代表を選び、コメントを取る | | |
| 〜+数時間 | 「AI の番」 | コメント分析（動画1本ずつ）、執筆。数回の毎時実行に分かれる | |
| 任意 | 「レポートができました」 | | 読んで、修正案と考察を書いて送る |
| 〜+1h | | 該当の章を書き直す | ダウンロード |

- 利用者が手を動かすのは **開始・軸の確認・段階の確認・レポートの修正の4回**
- 全体は**1〜2日**。待ちのほとんどはコメント取得と、利用者が確認に来るまでの時間
- 急ぐときは、定期実行を待たずに Claude で依頼文を1回打てば、その場で進む

## 3. ChatGPT を選んだ人の使い勝手（手順が多い。未確定）

ChatGPT のデスクトップアプリには **Codex** が入っている。Codex にはサービスの接続を足せる（[Codex の MCP 設定](https://learn.chatgpt.com/docs/extend/mcp)）。

### 最初の1回だけ

1. ChatGPT の有料プランを契約し、デスクトップアプリを入れてログイン
2. 設定 → MCP サーバー → 「サーバーを追加」→ 種類「Streamable HTTP」、URL を貼る → 保存 → **再起動** →「認証」を押してサービスにログイン
3. Codex で依頼文を打つ

### Claude より弱い点

- Codex は**開発者向けの画面**で、手順も一段多い。IT リテラシーゼロの人が自分で設定するのは難しい（運営が一緒にやれば可能）
- **Cowork のような定期実行を、この接続と組み合わせて使えるかは確認できていない。** できなければ、AI の番が来るたびに利用者が Codex で依頼文を打つことになる
- ChatGPT のチャット側にも「開発者モード」で外部の接続を足す方法があり、Plus でも個人で使える。ただしチャットの形なので、仕事の多さ（第1章）に合わない。書き込みの操作に毎回確認を求められる場合もある
- 使える有料プランの範囲（Plus で足りるか）は未確認

## 4. サービス側で作るもの

| 作るもの | 中身 |
|---|---|
| 接続口（MCP サーバー） | 公開 URL で動かす。Claude のコネクタは Anthropic のクラウドから届くので、公開されている必要がある（今の ngrok の URL で届く） |
| 利用者ごとの URL | その人専用の秘密の URL にして、**ログイン操作をなくす**（3人なので十分）。人数が増えたら、サービスへのログイン（OAuth）に切り替える |
| 道具 | 「自分宛ての仕事を1つ取る（指示書と入力、サムネの一覧画像も）」「出力を返す（検査して、だめなら理由を返す）」「今の状況を見る」の3つ程度 |
| 仕事の大きさ | 1つの仕事が AI に収まる大きさに切る（ラベルは数十本ずつ、コメント分析は動画1本ずつ、執筆は章ごと） |
| 途中で止まってもよい作り | 定額プランの利用上限に当たったら、そこで止まり、次の定期実行で続きから |

Claude と ChatGPT で**サービス側は同じもの**。違うのは利用者のアプリでの最初の設定だけ。

## 5. 作り込む前に試すこと（先行検証）

ここに書いたことは説明ページを読んだだけなので、作り込む前に、道具2つだけの試作の接続口を立てて、実機で確かめる（半日程度）。

| # | 確かめること | 分かれ目 |
|---|---|---|
| V1 | Claude デスクトップでカスタムコネクタ（URL だけ、ログインなし）を追加し、Cowork から道具を呼べるか | 呼べなければ第2章が崩れる |
| V2 | **Cowork の毎時の定期実行から、そのコネクタを使って仕事を取り、返せるか。** 道具を使うたびに承認を求められないか | 求められるなら「一言も打たない」は成り立たない |
| V3 | 道具の返り値の画像（サムネの一覧）を AI が読めるか | 読めなければ画像はファイルで渡す別の手が要る |
| V4 | 1回の実行で何件の仕事をこなせるか、Pro の利用上限をどれだけ使うか（シルエットの E2E の入力で測る） | Pro で1日に1分析が回るか、Max が要るか |
| V5 | ChatGPT デスクトップの Codex で同じ接続を追加でき、道具を呼べるか。定期的に自動で動かす手段があるか | ChatGPT を最初から選べるようにするか、Claude だけで始めるか |

検証に要るもの: Claude の Pro 以上のアカウント（運営のものでよい）、ChatGPT の有料アカウント（V5 用）。

## 6. サービス側から仕事を投げる形（2026-09-30 追記）

「仕事が出来たら、サービスが利用者の AI を起こして仕事をさせる」形。利用者は Claude も ChatGPT も開かない。

### 6-1. 調べて分かったこと

| | 定額プランのまま投げられるか | 仕組み | 注意 |
|---|---|---|---|
| **Claude** | **できる（公式）** | **Claude Code の「ルーティン」**。指示文と接続を保存した自動実行で、**専用の URL にサービスが POST すると、Anthropic のクラウドで1回実行される**（[ルーティンの説明](https://code.claude.com/docs/en/routines)、[起動 API](https://platform.claude.com/docs/en/api/claude-code/routines-fire)）。PC は閉じていてよい。実行中は接続（サービスの道具）を承認なしで使う。使った分は利用者の定額プランの枠から引かれる | 研究プレビュー（仕様が変わりうる）。**ルーティンには GitHub のリポジトリを1つ以上選ぶ作りで、利用者の GitHub アカウントの連携が要りそう**（指示書を置いた運営の公開リポジトリを選ばせる想定。要確認）。起動は1ルーティンあたり1時間に30回まで |
| **ChatGPT** | **直接はできない** | ChatGPT には外から起動する URL（webhook）が無い。近いものが2つ: ①**Gmail に特定の差出人からメールが届いたら動く**タスク（サービスが利用者の Gmail にメールを送れば、実質「投げる」になる）、②**分単位の間隔で繰り返す**タスク（数分おきにサービスに仕事を見に来る）。どちらも Web 版ならクラウドで動く（[定期・イベントのタスク](https://learn.chatgpt.com/docs/automations)） | **このタスクから、利用者が足したサービスの接続（開発者モードの MCP）を使えるかは、説明に書かれていない**。使えなければ成り立たない。①は利用者が Gmail を使っている前提 |
| ~~両方（API キー）~~ | **採らない**（ユーザー判断: 通常のプランの中で使えないので不可。一般的な利用者は API を契約しない） | — | — |

### 6-2. 利用者の使い勝手（投げる形）

| | 最初の1回（運営が一緒に） | 以後 |
|---|---|---|
| Claude（ルーティン） | Pro 以上を契約 → claude.ai でサービスの接続（専用 URL）を追加 → ルーティンを作る（運営が用意した指示文を貼り、運営の公開リポジトリを選び、起動方法「API」）→ 出てきた URL と鍵をサービスの画面に貼る。GitHub 連携が要るなら、その作成と連携も | **何もしない。** サービスの画面で開始・確認・修正するだけ。AI の番が来たら、サービスが即座にルーティンを起こす |
| ChatGPT（Gmail 起動 or 数分おき） | 有料プランを契約 → 開発者モードでサービスの接続を追加 → タスクを作る（「サービスからメールが来たら仕事を片付けて」または「10分おきに仕事を片付けて」） | 何もしない（使えると確認できた場合） |

### 6-3. 私の案（通常の定額プランだけ、Claude・ChatGPT 両対応）

前提（ユーザー、2026-09-30）: **API は使わない。** 一般的な利用者が持っているのは Claude の Pro/Max か ChatGPT の Plus/Pro だけ、という想定で作る。

定額プランの中で、サービスから AI を**即座に**起こせる公式の仕組みは、今のところ **Claude のルーティンだけ**。ChatGPT には無い。
そこで、**利用者から見て「投げる形」と同じに見える**ことを目標に、次の2段で作る。

| | 基本（両方で同じ作り） | 使えれば足す |
|---|---|---|
| 仕組み | 利用者の AI に**定期実行のタスク**を1つ作ってもらい、AI が数分〜1時間おきにサービスを見に来て、仕事があれば片付ける | **Claude**: ルーティンの起動 URL で、仕事が出来た瞬間にサービスが起こす。**ChatGPT**: サービスが利用者の Gmail に通知メールを送り、それを合図にタスクが動く |
| Claude | Cowork の定期実行（最短1時間おき、クラウドで動く、接続とプラグインを使える） | ルーティン（GitHub 連携が要るかを W1 で確認） |
| ChatGPT | ChatGPT の定期実行（分単位の間隔が可、Web 版はクラウドで動く） | Gmail 起動 |
| 利用者から見て | AI のアプリは開かない。サービスの画面で開始・確認・修正するだけ。AI の番が来てから動き出すまでに最大で「定期実行の間隔」だけ待つ | 待ちがほぼ無くなる |

**両方に共通の急所は、定期実行のタスクから「サービスの接続」を使えるか**（Claude は説明ページで「使える」とある。ChatGPT は書かれていない）。ChatGPT で使えなければ、ChatGPT 対応はこの形では成り立たず、別の手を考える必要がある。

定額プランには**利用枠**がある（Claude は5時間ごと、ChatGPT も上限あり）。本番1回の AI の仕事（ラベル付け・コメント分析数十〜240本・執筆）は1つの枠に収まらない可能性が高いので、**枠に当たったら止まり、次の定期実行で続きから**を前提に作る。1回の分析が1〜2日にわたってもよい設計にする。

### 6-4. 先に確かめること（第5章を置き換え）

| # | 確かめること | 分かれ目 |
|---|---|---|
| W1 | Claude のルーティンを、**GitHub 連携なしで作れるか**（運営の公開リポジトリで足りるか） | 要るなら、利用者の最初の設定に GitHub が加わる |
| W2 | ルーティンを API で起こし、**サービスの接続（カスタムコネクタ）を承認なしで使って**仕事を取り、返せるか。サムネの一覧画像を読めるか | 成り立てば、Claude は定額プランのまま「投げる形」になる |
| W3 | 1回のルーティンで何件の仕事をこなせるか、Pro の枠をどれだけ使うか | Pro で足りるか、Max が要るか |
| W4 | ChatGPT の定期・Gmail 起動のタスクから、**開発者モードで足したサービスの接続を使えるか**。分単位の間隔で回せるか | 使えなければ、ChatGPT 対応は別の手を考える |
| W5 | 本番1回分（E2E の入力）を定額プランで流し、枠をどれだけ使うか・何回の定期実行に分かれるかを測る | Pro/Plus で足りるか、Max/Pro が要るか。利用者に伝える所要日数 |

W1〜W3・W5 は運営の Claude アカウント（Pro 以上）、W4・W5 は ChatGPT の有料アカウントが要る。

## 7. 「Claude Code のような形」で作る（2026-09-30 追記。ユーザーの理想）

ユーザーの理想: **Claude Code のように、利用者が自分のアカウントでログインして、そのまま使える状態。** API は使わない、Claude・ChatGPT 両対応は必須、一般的な利用者が前提。

### 7-1. 作り方は2通りあり、規約で分かれる

| | A. 自前のアプリに「Claude／ChatGPT でログイン」を付ける | B. 利用者が**本物の Claude／ChatGPT のアプリ**にログインし、その中で**サービスのプラグイン**を使う |
|---|---|---|
| 仕組み | サービス（またはサービスが配るアプリ）が、利用者の定額プランで AI を動かす | 利用者の Claude（Cowork・Claude Code）や ChatGPT（Codex）が AI を動かし、サービスはプラグインとして「手順（スキル）」と「道具（接続）」を渡す |
| Claude | **不可。** 「承認が無い限り、第三者の開発者が自分の製品で claude.ai のログインや利用枠を提供することを認めない」と公式に明記（[Agent SDK の説明](https://code.claude.com/docs/en/agent-sdk/overview)） | **可。** プラグインは Pro 以上で、チャット・Cowork・Claude Code で使える。リポジトリの URL かファイルで追加できる（[プラグインの説明](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)） |
| ChatGPT | 不明。Codex を自社製品に組み込む口（App Server）は公開されているが、ChatGPT のログインを使ってよいかは書かれておらず、**本番利用は非対応（実験的）**と明記（[App Server](https://learn.chatgpt.com/docs/app-server)） | 可能性が高い。ChatGPT／Codex にもスキルと接続を束ねたプラグインがある（[プラグイン](https://developers.openai.com/plugins/deploy/connect-chatgpt)）。**利用者が URL から入れられるか、公開の審査が要るかは未確認** |

→ **B で作る。** 利用者から見ると Claude Code そのものなので、理想の「ログインしてそのまま使える」に一番近く、規約にも沿う。E2E 試験は実際にこの形（Claude Code が全工程を回した）で成功している。

### 7-2. B の使い勝手

**最初の1回**: Claude か ChatGPT のデスクトップアプリを入れてログイン → サービスの「UGC 分析プラグイン」を追加（運営が渡すリンクから）。

**分析のたび**（Claude の Cowork の例）:

| 利用者 | AI（利用者の Claude） | サービス（Windows 機） |
|---|---|---|
| 「KANA-BOON のシルエットを分析して」と打つ | サービスに動画一覧と属性の取得を頼み、「取得に1時間半ほどかかります。終わったらお知らせします」と返す | 一覧・属性・サムネを取る。終わったら利用者にメールで知らせる |
| 「続けて」と打つ | 集計を読み、分類の軸の案を出す:「界隈は次の10個に分けました。直したいところはありますか」 | |
| 「タレントとインフルエンサーは分けて」 | 直して確定、ラベル付け、段階の案 →「段階はこの4つです」 | |
| 「それでいい」 | 代表を選び、サービスにコメント取得を頼む:「3時間ほどかかります」 | コメントを取る。終わったらメール |
| 「続けて」 | コメント分析、執筆 → レポートをファイルで渡す | |
| 読んで「3章に音楽面の話を足して。〇〇は△△」 | 該当の章を書き直す | |

- **確認は会話の中でする。** 前に決めた「AI の案を md で書き出し → 直してアップロード」は、この形では要らなくなる（直したいところを話しかければよい。ファイルで直したい人は、AI が書いたファイルを直接直してもよい）
- 待ちの間は会話が止まる。取得が終わったらサービスがメールで知らせ、利用者が「続けて」と打つ
- 利用枠に当たったら、アプリが「〇時まで待って」と言うので、その後に「続けて」と打つ
- サービスの Web 画面は、進み具合・取得データ・成果物のダウンロード用に残す

### 7-3. サービス側で作るもの（B）

| 作るもの | 中身 |
|---|---|
| プラグイン（Claude 用・ChatGPT 用） | **スキル**＝分析の手順と各工程の指示書（今の `analysis/prompts/` を汎用化したもの。両方でほぼ共通の Markdown）、**接続**＝サービスの道具への URL |
| 道具（MCP サーバー、公開 URL） | 「一覧・属性の取得を始める」「コメント取得を始める」「進み具合を見る」「データを読む（集計表・動画ごとのコメント・サムネ一覧）」「成果物を保存する」「検算する」 |
| 利用者の識別 | プラグインの接続を利用者ごとにする（運営が3人分を発行） |
| 知らせ | 取得が終わったらメール |

### 7-4. 先に確かめること（第6章の W を置き換え）

### 7-5. 台本はサービスが持ち、AI は実行係にする（2026-09-30 追記）

ユーザーの要望: AI にやらせることはこちらで型を作っておきたい。楽曲分析を走らせたら、あとは最後まで走り切ってほしい。AI への指示はほぼ定型で、例外は界隈分類の確認だけ。

**作り方**: 手順（どの工程を、どの順で、どの指示書で）は**サービスが持つ**（前に設計した Step の並びと runner）。プラグインに入れるのは、次の短い定型の指示だけにする。

> UGC 分析: サービスに「次の仕事」を聞く → 仕事に付いている指示書と入力のとおりに作業する → 結果を返す → また聞く。
> サービスが「利用者の確認待ち」と言ったら、案を利用者に見せて返事をもらう。「取得待ち」と言ったら待つ。「完了」と言ったら終わる。

- AI は全体の流れを知らなくてよい。1つの仕事＝1つの指示書（分類の軸の提案、ラベル付け数十本、動画1本のコメント分析、章1つの執筆…）で、サービスが用意する
- 返ってきた結果はサービスが検査し（形式、コメント ID の実在、数値の一致）、だめなら理由をつけて同じ仕事を差し戻す
- **手順や指示書を直しても、利用者はプラグインを入れ直さなくてよい**（サービス側だけ変わる）。ワークフローを後から足すときも同じ
- Claude と ChatGPT で、プラグインの中身（定型の指示）と、サービスが渡す指示書は共通

**人が止めるのは界隈分類の確認（H1）だけ。** 段階の確認（H2）は置かず、自動で確定する（ユーザーの「定型になる（界隈分類の確認以外）」から。段階を直したければ、出来上がった後のレポート修正で言う）。

**「最後まで走り切る」の障害は2つ。**

| 障害 | 中身 | 対処（案） |
|---|---|---|
| 取得の待ち | 一覧・属性で約1.5時間、コメントで数時間〜12時間。その間 AI の出番は無い | ①AI の会話を開いたまま、サービスの「終わるまで待つ」道具を繰り返し呼んで待つ（Cowork で何時間も待てるかは未確認）、②利用者の AI の定期実行（Claude Cowork は1時間おき、ChatGPT は分単位）で続きを拾う、③Claude はルーティンでサービスから起こす。どれも駄目なら、取得完了のメールを見て利用者が「続けて」と打つ |
| 利用枠 | 定額プランには枠がある（Claude は5時間ごと）。本番1回分は1つの枠に収まらない可能性が高い | 枠に当たったら止め、②の定期実行で自動再開。駄目なら利用者が「続けて」 |

**利用者から見た流れ（目標）**: 「シルエットを分析して」→（1〜2時間後）「界隈の案です。直すところはありますか」→ 答える →（半日〜1日後）「レポートができました」。触るのは3回（開始・界隈の確認・レポートを読む）、直したければもう1回。

**試作で追加で確かめること**: P5 Cowork の1つの会話で、取得を何時間も待ってから自分で続きに進めるか。P6 定期実行で、止まった分析を自動で拾って再開できるか（Claude・ChatGPT）。
