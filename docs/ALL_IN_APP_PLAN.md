## 0. 目指す形

**友達の Mac に入れるアプリ1つに、取得も、AI の相手（仕事の列・指示書・検査・データ・知識ベース）も、全部入れる。サーバーは使わない。**

- 友達は自分の Claude に「〇〇を分析して」と言う → その Mac のアプリが取得する → 翌日「続けて」→ レポートがその Mac にできる
- 運営の Windows 機・ngrok は、友達の経路に出てこない。運営が見張る・保守するものは無い
- 指示は友達が自分で変えられる。知識ベースは自分で新しくなる

## 2. 友達から見た形

**最初の1回**（運営が LINE 通話で付き添う）

1. Claude デスクトップアプリを入れてログイン（Pro 以上）
2. 取得アプリ（.dmg）を入れる →「このまま開く」
3. 取得アプリが開いた Chrome で、捨て垢にログイン
4. 取得アプリのメニュー「Claude につなぐ」を押す → Claude を開き直す

秘密の URL を貼る・接続を足す・番号を言う、は無くなる。

**分析のたび**

1. Claude に「〇〇を分析して」→ 楽曲ページを確かめる（「この曲で合っていますか」）→ 取得が始まる
2. Mac を開いたまま・電源につないで、13時間前後。終わると Mac の通知
3. Claude に「〇〇の分析を続けて」→ 界隈の案に答える → あとは1.5〜3時間、Mac と Claude を開いたまま
4. レポートはその Mac のフォルダにできる（メニュー「レポートのフォルダを開く」）

**指示を変えたいとき**（N2）: Claude に「今後は文体をもっとくだけた感じにして」と言う。もっと細かく直したい人は、メニュー「指示書を編集」。
**知識ベース**（N3）: 何もしなくても、新しい記事が出たら次の分析のときに取り込まれる。

公式の説明は「作業がクラウドで動いていても、その Mac で Claude デスクトップが開いていればローカルの接続は使える」。実機ではまだ試していない。

### 段1: AI の相手と道具をアプリに入れる

- 本線の型（`proto_runner.py`・`flow_w1.py`・`user_settings.py`・指示書）をアプリに同梱する。データの置き場を Mac のフォルダにする。利用者は1人で固定
- 道具7つを、アプリの実行ファイルが Mac の中の道具として出す
- 「分析を始める」: Mac の中に分析を作る → メニューバーの取得アプリが拾って取得する（試作の仕組みをそのまま使う）。取得アプリが起動していなければ起こす
- **楽曲ページの確かめ**: 曲名で頼まれたら、AI が TikTok の楽曲ページを検索で探し、利用者に「この曲で合っていますか」と確かめてから渡す。
  今までの検索は鍵つきの検索サービス（Windows 機にしか鍵が無い）に頼っていて、Mac では一度も動いていない。この形なら鍵が要らず、「最初に見つかったページを確かめずに使う」という既知の弱点も消える
- 「状態」と待ちの文面: 「取得中（コメント 35/197本、〇時ごろ終わる見込み）」「取得アプリが止まっています。開けば続きから取ります」。メールの文言は消す
- 完了の文面: ダウンロードのリンクをやめ、Mac のフォルダの場所を伝える

### 段2: 「Claude につなぐ」・メニュー・通知

- メニュー「Claude につなぐ」: Claude デスクトップに道具を登録する（Claude の設定ファイルは控えを取り、ほかの設定には触らない）。登録の方法は段0で通ったものを使う
- メニューの整理: 状態の1行／止まった取得を続きから再開／取得の画面を見る・しまう／TikTok にログイン／Claude につなぐ／レポートのフォルダを開く／指示書を編集／ログイン時に起動／終了。
  「曲を取得する…」「ちょいとり…」は運営向けに隠す
- 通知の文面: 「〇〇の取得が終わりました。Claude で『〇〇の分析を続けて』と言ってください」
- 試作のときに残った確かめ: 取得用の Chrome が最小化のまま回るか
