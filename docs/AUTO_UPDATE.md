# 自動の更新（0.9.0〜）

UGC Analyzer が新しい版を自分で見つけて入れ替える仕組みと、運営（ユーザーと Claude）の出し方。
見え方の見本（ユーザーが 2026-10-31 に確かめたもの）: https://claude.ai/artifact/UCfG8e4oXC2F6GdZY2nB8N （元 `docs/pages/update-preview.html`）

## 1. 決めたこと（2026-10-31 ユーザー）

- きっかけ: 「バージョンアップが不便。ほかのアプリみたいに通知が出て、自然にアップデートがかかるように」。いままで友達は、LINE を待って6つの手順（終了 → 落とす → 置き換える → 開く・このまま開く → Claude を開き直す → 番号を見る）で入れ替えていた
- **友達に届くのは、ユーザーが「〇〇を友達に出して」と言ったときだけ**（案1）。Claude が直して出す版は試し版のまま。試していない版を友達に届けない（10/12 の 0.7.5 の行き止まりのようなことを、友達の手元で自動で起こさない）
- **空いていれば黙って入れ替える**: Claude・ChatGPT が閉じていて作業中でもなければ黙って入れ替えて通知。開いていれば窓で［今すぐ新しくする］［あとで］。取得中・AI の作業中は待つ
- メニューに **「新しい版を確かめる…」をいつも出す**（ほかのアプリの「アップデートを確認」と同じ）。使い道は、運営が直してすぐ入れてほしいとき（「割れた音符 →『新しい版を確かめる』を押して」と頼む）。自分から見に行くのは3時間おきなので、それを待たずに入れられる
- 手順書（始め方のページ・紙・LINE）も書き直す

## 2. 友達から見た流れ

| 場合 | 条件 | 起きること | 友達がすること |
|---|---|---|---|
| A 黙って | Claude・ChatGPT が閉じている（つないであって動いているものが無い）・作業中でない | 入れ替えて開き直し、通知「UGC Analyzer を 〇〇 にしました」 | なし |
| B 窓で聞く | Claude（ChatGPT）を開いている・作業中でない | 窓「UGC Analyzer の新しい版（〇〇）があります」（1日1回まで）。「今すぐ」→ 入れ替え → Claude を開き直す → 通知。「あとで」→ 次に Claude を閉じたとき A | ボタンを1回 |
| C 待つ | 取得・取り足し・順番待ち・取り直しの予定・TikTok のロック、AI が道具を最後に使ってから15分以内、Code タブで待っている | メニューに灰色の「新しい版 〇〇 は、取得（AI の作業）が終わったら入れます」 | なし |

- メニューの行: ふだん「新しい版を確かめる…」 → 用意している間「新しい版 〇〇 を用意しています…」（灰色）→ 用意できたら「新しい版 〇〇 にする…」→ 作業中は灰色の「…が終わったら入れます」
- 押したとき: 新しい版が無ければ「いまの版（〇〇）が最新です」、確かめられなければ「新しい版を確かめられませんでした」
- 窓と通知の「今回の版: …」の1行は、`release.sh --friends --note` で書いたもの（無ければ出さない）
- 入れ替えられなかったとき（アプリケーションフォルダの外で動いている・Mac に断られた）: 前の版のまま開き、窓「自動で新しくできませんでした」［手順を開く］（始め方のページの「新しい版にするとき」）。その版は、もう自分からは入れない（メニューからは試せる）

## 3. 運営の出し方（collector/release.sh）

| 段 | 命令 | 起きること |
|---|---|---|
| 試し版 | `collector/build.sh` → コミットを push → `collector/release.sh` | GitHub に prerelease で載る。友達には届かない（友達のリンクも前の版のまま）。**運営の Mac（`DATA_DIR/operator` がある）は試し版も受け取る**ので、友達と同じ入れ替えの道を先に通る（Claude を開いていれば窓が出る） |
| 友達に出す | ユーザー「〇〇を友達に出して」→ 始め方のページと紙の「いまの版は UGC Analyzer 〇〇」を直してページを公開し直す → `collector/release.sh --friends 〇〇 --note "今回の版の1行"` | その版が latest になる。友達の UGC Analyzer（0.9.0〜）は3時間以内に自分で入れ替える。友達のリンクもこの版になる |

- `--note` は友達向けの言葉で1文（例「コメントの取り足しが途中で止まることがあったのを直しました」）。裏の仕組み・道具の名前・日付を書かない（友達向けの文の決まり）。省くと、前に書いたものを残す
- `--friends` は「いまの版は」が出す版と食い違うと止まる（2026-10-12 からの決まりを、こちらの段に移した）
- LINE は要らない。大きく変わったことを伝えたいときだけ（`docs/LINE_MESSAGES.md` 第4章）
- 0.8.1 までの友達には、この仕組みが無い。0.9.0（以降）を友達に出すときだけ、手で入れ替えてもらう（`docs/LINE_MESSAGES.md` 第7章）

## 4. 仕組み（collector/collector_app/updater.py・app.py）

1. **見に行く** `updater.latest_release`: アプリを開いた1分後・Mac が起きた1分後・3時間おき・メニュー。友達は `GET /repos/…/releases/latest`（prerelease を含まない）、運営の Mac は `/releases?per_page=20` から試し版も。`.dmg`（`UGC-Analyzer.dmg`）の付いた、いちばん新しい版
2. **落として確かめる** `updater.stage`（裏のスレッド）: `DATA_DIR/updates/UGC-Analyzer-<版>.dmg` に落とす → 大きさと sha256（GitHub の asset の digest）→ `hdiutil attach` で開き、中の `UGC Analyzer.app` の識別子（`jp.ugc-analyzer.collector`）と版 → `updates/staged/<版>/` に ditto → 写した .app を `--selftest`（一時の置き場で。build.sh の自己点検1と同じ）。だめならそこまでのものを消して、次の確かめ（3時間後）でやり直す。用意した版は `state.json` の `update.staged`
3. **決める** `updater.decide`（見張りの5秒おき）: 作業中 → 待つ。メニューから → 窓。入れられなかった版（`update.failed`）→ 自分からは入れない。AI が閉じている → 黙って。開いている → 今日まだ聞いていなければ窓（`update.asked_on`）
4. **入れ替える** `updater.apply` → `updates/swap.sh`: `state.json` に `update_pending`（from・to・mode・開き直す AI・今回の版）を書き、係を別のセッションで起こしてからアプリを終える。係はアプリの PID が消えるのを待ち（2分まで）、今の .app を `updates/backup/UGC Analyzer.app` へ（控えは1つだけ）、用意した .app を元の場所へ移して開く。どこかで失敗したら前の版を元に戻して開く。記録は `logs/update.log`
5. **新しい版で開いたとき** `app.update_notice`: `update_pending.to` が自分の版なら通知を出し、用意したものを片付ける。`mode="now"`（窓で「今すぐ」）なら、前の版の道具が動いている AI を聞かずに開き直す（`version_notice` の `startup_restarts`）。自分の版が `from` のまま（入れ替えられなかった）なら、`update.failed` に書き、窓で手の入れ替えを頼む

- アプリが自分で落としたファイルには、Mac のダウンロードの印（`com.apple.quarantine`）が付かない。2回目からは「開いていません」「このまま開く」が出ない
- 別の .app（新しい版）を起こすときは、PyInstaller の起動の印（`_PYI*`）を持ち越さない（`updater.clean_env`。持ち越すと起こした方の中身を読むことがある）
- 係の bash（macOS の 3.2）は、変数のすぐ後ろの全角の文字の一部まで名前として読む。変数はいつも `${…}` で囲む（試験で記録の文字化けとして出た。release.sh・install.sh の文も直した）
- AI の作業の見分けは `logs/mcp.log`（Claude・ChatGPT の道具の処理が全部書く。前の版の道具も）の更新から15分と、`--wait` の処理

## 6. 運営向けの困ったとき

- 自動で入らない: `logs/collector.log` の「新しい版」の行、`logs/update.log`、`state.json` の `update`（staged・asked_on・failed・check_error）を見る。`update.failed` を消すと、その版を自分からまた入れる
- 運営の Mac で試し版を受け取りたくない: `DATA_DIR/operator` を消す（運営向けのメニューも消える）。ふつうは消さない
- まずい版を友達に出してしまった: 古い版には戻さない作り（版の番号が上がるときだけ入れ替える）。直した版を出す
