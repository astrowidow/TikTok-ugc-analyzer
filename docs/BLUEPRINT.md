# これでいける案 — 「2回着席」方式（2026-09-30）

条件（ユーザー）: 利用者の負担が最小／AI の枠を無駄にしない／人の介入は理想2回でレポートが仕上がる／インストールは簡単（ここは一番妥協できる）／
API は使わない（一般の Claude・ChatGPT の利用者）／Claude と ChatGPT の両対応は必須／型はサービスが持つ。

---

## 1. 結論

**利用者が自分の AI（Claude か ChatGPT）に「分析して」と言う。翌日もう一度「続けて」と言い、界隈の案に一言答える。それで終わり。**

- 人の介入は **2回**（開始／界隈の確認）。2回目の着席で「続けて」と界隈の確認を同時に済ませるので、増えない
- AI の枠を使うのはこの2回の着席の間だけ。**待っている間は何も動かないので枠を使わない。** 見に来る（ポーリング）も、予約も、GitHub 連携も要らない
- Claude・ChatGPT で**同じ作り**。違いは「接続を足す」手順だけ
- 取得は運営の Windows 機（実証済みの経路）。AI の作業は利用者のアプリの中（E2E で実証済みの形）

これを成り立たせる発想の転換は3つ（第2章）。3つ目の転換の核になる仮説は、手元のシルエットのデータで試して成り立った（第3章）。

---

## 2. 3つの転換

### 転換1: 取得を全部先に済ませ、AI の出番を「1回の連続した区間」にまとめる

これまでの手順は「取得 → AI（分類）→ 取得（コメント）→ AI（分析・執筆）」で、AI の出番が2回に割れていた。
割れているから「取得の間 AI をどう待たせるか・どう起こすか」が問題になった。

**コメントを取る対象を、AI の分類より前に、数字と属性だけの規則で決める**（＝候補プール）。そうすると取得は
「一覧 → 属性 → コメント（プール）」と一気に終わり、AI は**そのあと1回だけ**、分類からレポートまで通しで走る。

代表動画の選定（界隈×段階のセルから選ぶ）はやめない。**AI はプールの中から選ぶ**。プールは代表に要る本数の3〜4倍あるので、ほとんどのセルに候補がある（第3章）。

副産物: **到達性の問題が消える。** プールは「今グリッドに見えている動画」から作るので、E2E で65本中38本を取りこぼした原因（9か月前のリストにあってグリッドに無い）が起きない。

### 転換2: AI は待たない・見に来ない。人が着席したときだけ動く

界隈の確認（H1）は、どのみち人が居ないと進まない。**だから2回目の着席は必ずある。** その着席の冒頭で AI を起こせば、それ以外に AI を起こす仕組みは要らない。

- 「AI に何時間も待たせる」「定期的に見に来させる」「サービスから起こす」は全部不要（第6章に比較を残す）
- 2回目の着席で利用者がやるのは「続けて」と打つこと、界隈の案に答えること、の2つ。あとは閉じてよい（Claude Cowork はクラウドで動く）

### 転換3: 型はサービス、AI は実行係。プラグインの中身は一言

手順・指示書・検算・状態は全部サービスが持つ。AI に渡すのは「サービスに次の仕事を聞く → 指示書どおりにやる → 返す → 繰り返す」という短い定型だけ。
これで Claude・ChatGPT の両対応は「接続（サービスの道具）を足す」ことに縮む。手順を直しても利用者側は何も変えない。

## 3. 転換1の検証（手元のデータで実施、2026-09-30）

シルエット（880本）で、E2E が実際に選んだ代表65本（界隈×段階のセル38個）を、**AI を使わない規則で作ったプール**がどれだけ含むかを測った。

- 残りを週ごとに配分（週の本数の平方根に比例）。週の中では、**投稿地域ごと・TikTok のカテゴリラベルごと**に最大再生を1本ずつ → 残りは上位半分＋無作為半分

| 99 | 5.0 時間 | 39 | 26 |
| 136 | 6.8 時間 | 43 | 28 |
| 170 | 8.5 時間 | 48 | 30 |

→ **12時間の取得1回で、E2E が必要とした代表のほぼ全部を、AI の分類を待たずに取れる。** 小さなセルは「候補が無い」とレポートに書く（E2E と同じ扱い）か、利用者が望めば追加取得（3回目の着席）。

## 4. 使い勝手（利用者から見た画面）

利用者が触るのは**自分の Claude（または ChatGPT）だけ**。サービスの Web 画面は進み具合と成果物のダウンロード用で、開かなくてもよい。

### 最初の1回（運営が横で一緒に。10〜15分）

1. Claude デスクトップアプリを入れてログイン（ChatGPT は Plus 以上で、Web 版。第7-1節）
2. 運営が渡した接続（その人専用の URL）を足す。Claude は「カスタマイズ → コネクタ → ＋」、ChatGPT は開発者モードをオンにしてアプリ（MCP サーバー）を追加
3. ~~（Claude）運営が渡したプラグインを追加。（ChatGPT）同じ中身のスキルを入れる~~ → 定型の指示は接続から渡すので、原則不要（第7-1節。T1 で要ると分かったときだけ）

### 1回目の着席（1分）

> 利用者: **KANA-BOON の「シルエット」を分析して**
> AI: 楽曲ページを見つけました。動画一覧・属性・サムネの取得と、候補約220本のコメント取得を始めます。合計で13時間ほどかかります。終わったらメールでお知らせするので、そのあと「続けて」と言ってください。

利用者はアプリを閉じてよい。この間、AI は動かず、枠も使わない。

### 2回目の着席（10〜20分。ここだけ人が要る）

翌日、メール「シルエットの取得が終わりました」。

> 利用者: **シルエットの分析を続けて**
> AI: 880本の属性と週ごとの推移を読みました。（数分）
> AI: **界隈の案です。** ①海外ダンス（起点はミャンマー、7月）②国内ダンススタジオ ③一般の女子高生 ④タレント・インフルエンサー ⑤コスプレ ⑥K-POP ⑦家族 ⑧解説系 ⑨テレビ局・企業 ⑩広告 — 各界隈の見分け方と代表例は添付の表のとおりです。**分け方を変えたいところはありますか？ このままでよければ「OK」と言ってください。**
> 利用者: **④はタレントとインフルエンサーで分けて。あとは OK**
> AI: 分けました。ここから先は確認なしで進めます。ラベル付け → 段階の区切り → 代表の選定 → コメント分析 → 執筆 → 仕上げ、で2〜3時間の見込みです。閉じても大丈夫です。

利用者はここで閉じてよい。

### 完了（半日後）

> AI: **レポートができました。** 拡散経路は4段階（海外起点 7〜8月 → 日本輸入 8〜10月 → 国内拡大 10〜11月 → 定着 12月〜）。note 用の原稿と Excel 用のデータもサービスに保存しました。
> ［REPORT.md］［NOTE_BODY.md］［データ.zip］
> 音楽面・時代背景・TikTok 外の指標は「人の考察を入れる場所」として空けてあります。

### 直したいとき（任意）

> 利用者: **3章に音楽面の話を足して。サビ前のブレイクが効いてると思う**
> AI: 3章を書き直しました。

### 指示を変えたいとき（任意、2026-09-30 追加）

> 利用者: **今後はレポートの文体をもっとくだけた感じにして**
> AI: 文体の設定を変えました。次の分析から使います。

変えられるのは4項目（文体／レポートの重点／界隈の分け方の方針／コメント分析の観点）。保存先はサービスで、利用者ごと。デフォルトはこちらで設定。
出力の形・検算・繰り返し方は変えられない。Web 画面には行かない。

**利用者向けの Web 画面は作らない。** 進み具合は会話、取得の完了はメール、成果物は AI とメールが出すダウンロードのリンク。
接続はアプリのコネクタに1回だけ登録（試作は利用者ごとの秘密の URL）。プラグインは使わない。

### 枠に当たったとき（小さいプランで起きうる）

> AI: 利用枠の上限に達しました。〇時に戻ります。そのあと「続けて」と言ってください。続きから再開します。

何も失われない（サービスが済んだ仕事を持っている）。介入が1回増えるだけ。

## 5. サービス側の作り（要点だけ）

| 部品 | 中身 |
|---|---|
| 接続口（MCP、公開 URL、利用者ごとの秘密 URL） | 道具は6つ程度: `start_analysis`（楽曲 → 取得開始）／`status`／`next_task`（次の仕事: 指示書＋入力）／`submit`（結果を返す。検査して、だめなら差し戻し）／`read`（集計表・動画1本のコメント・サムネ一覧などを読む）／`save_artifact` |
| 取得の段（Windows 機、待ち行列で直列） | 一覧 → 属性・サムネ → **プールの決定（第3章の規則）** → コメント（プールを、グリッドに見えている順に。12時間で打ち切り） → メール |
| AI の段の台本（runner） | 軸の提案 → ★確認 → ラベル（プール＋上位・最初期、30本ずつ）→ 段階（区切り候補は数字で、名前は AI）→ **代表の選定（セル配分はサービスの数字。プールの中から）** → コメント分析（動画1本ずつ）→ 統合 → 執筆（章ごと）→ 仕上げ → 検算 |
| 状態 | 分析ごとのフォルダ（原本・記録・計算物・成果物）と台帳。どの仕事が済んだかを常に持つ → どこで止まっても続きから |
| 知らせ | 取得が終わったらメール |

AI の作業量の見積（シルエット規模）: ラベル約300本、コメント分析約60本×40件、執筆8章＋知識ベース。**合計で入力100〜200万トークン程度**（実測が要る）。
Max なら一気に、Pro では5時間枠を1〜2回またぐ可能性がある（そのときは「続けて」が1〜2回増える）。

## 7. 犠牲にするもの・まだ確かめていないこと

**犠牲**

- 取得が全員13時間前後になる（一覧1.5時間＋コメント12時間弱）。運営機1台で**1日1分析**。利用者3人なら回る。プールを170本（8.5時間）に減らすと1日2分析だが、セルの覆いが少し下がる（第3章の表）
- 小さなセル（ラベル1〜7本）はプールに入らないことがある。E2E でも同じセルは取れていなかった
- 決定済みの「代表を選んでからコメントを取る」順が、「プールを取ってから代表を選ぶ」に変わる（第8章）

**未確認（実機で試す。順に）**

| T1 | Claude デスクトップの Cowork で、接続を足し、プラグイン（または一言の指示）で、2回目の着席の作業（ラベル〜執筆）を一気に回せるか。サムネ一覧を道具経由で読めるか。閉じても続くか | 作業を「続けて」で刻む（介入が増える） |

### 7-1. プランの調べ（2026-09-30）

| | 自前の接続（カスタム MCP）を足せるか | 定型の指示を入れる場所 | 結論 |
|---|---|---|---|
| ChatGPT 無料・Go | **足せない**。開発者モードは Plus・Pro・Business・Enterprise・Edu の Web 版のみ（2026年8月時点）。無料で使えるのは OpenAI の審査を通って一覧に載ったアプリだけ | 個人のスキルは無料・Go では作れない | **この方式では使えない** |
| ChatGPT Plus 以上 | 足せる（Web 版） | スキル（有料） | 使える見込み。書き込みの道具の扱いは情報が食い違っている（T2） |
| Claude 無料 | 1つまで足せる | プラグインは有料のみ | 接続は足せるが、枠が小さく実用は難しい見込み |
| Claude Pro 以上 | 足せる | プラグイン | 使える見込み（T1） |

→ **定型の指示はプラグイン・スキルに入れず、サービスの接続から渡す**（`next_task` が毎回指示書を返し、接続と道具の説明文に繰り返し方を書く）。
利用者が入れるのは接続1つだけになり、第4章の「最初の1回」の手順3（プラグイン・スキル）は、T1 で要ると分かった場合だけ足す。

## 8. 決定済みのことからの変更（**2026-09-30 承認済み**）

この変更をしないと、AI の出番がコメント取得の前後で2つに割れ、着席が3回になる（3回目は人の判断が要らず、AI を起こすためだけの着席）。

| 決定済み | 変更 | 理由 |
|---|---|---|
| 属性を取り尽くす → 軸を AI が提案し人が直す → 界隈×段階のセルで代表を選ぶ → **コメント** → 分析 → 執筆 | 属性を取り尽くす → **数字と属性の規則で候補プールを決めてコメントを取る** → 軸の提案・人の確認 → ラベル → セルで代表を**プールから**選ぶ → 分析 → 執筆 | AI の出番を1回にまとめるため。第3章のとおり代表のセル38中34を覆え、到達性の問題も消える。「再生数で一括に切らない」は守っている（最初期・公式・週ごと・地域ごと・ラベルごとに入れる） |
| 確認は「AI の案を md で書き出し → 直してアップロード」 | 会話の中で答える（Web からのアップロードは補助として残す） | 利用者が触るのを AI だけにするため |
| 段階の確認（H2） | 置かない（決定済み） | — |

## 9. 実装の順番（このあと私に投げてもらう前提）

実装の仕様と作法は `docs/IMPLEMENTATION_HANDOVER.md`（2026-09-30、別ウィンドウで実装する前提の引き継ぎ書）。

1. **試作の接続口**（道具4つ: status / next_task / submit / read）を Windows 機の Web サービスに足し、シルエットの手持ちデータで「2回目の着席」の中身を1つ流す → T1・T3 を測る（運営の Claude で）
2. 取得の段: プールの規則をコードにし、`spatest.py` を「プールをグリッドの順に取る」形に。一覧 → 属性 → プール → コメント → メールを1本の流れに
3. AI の段の台本: 指示書からシルエット固有の記述を外し、仕事の単位に切る。検算。代表のセル配分をサービス側の数字に
4. 利用者3人分の接続と、プラグイン（Claude）／スキルの入れ方（ChatGPT、T2）
5. シルエットで、利用者として2回着席で一周
