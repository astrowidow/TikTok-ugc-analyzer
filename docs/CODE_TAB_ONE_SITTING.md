# Code タブで、頼んでから完成まで一気に回す（案）— 2026-10-06

## 0. 一言で

Claude デスクトップの **Code タブ**（中身は Claude Code）なら、
「UGC Analyzer で〇〇／△△を分析して。界隈の確認はいらないので、そのまま最後まで書いて」の一言で、
取得（2〜3時間）を待ってから完成まで、利用者が戻らずに進められる見込み。

Code タブには「**裏で走らせたコマンドが終わると、Claude を起こし直す**」仕組みがあるから。チャットと Cowork には、この仕組みが無い。
いまは案で、作るものと実機の確かめが残っている（4〜6 章）。

## 1. なぜ今は着席が2回なのか

| | 中身 | 出どころ |
|---|---|---|
| 待てない | Claude デスクトップのチャット・Cowork は、道具1回の待ちが約60秒まで（延ばせない）。アプリから AI の会話を起こす手段も無い | `docs/DEEPEN_COMMUNITY.md` 3 章 |
| だから2回 | 取得が終わると Mac に通知が出て、利用者が「〇〇の分析を続けて」と言う（2回着席方式） | `docs/BLUEPRINT.md` |
| 自動化は見送り | 9/30 に「定期実行で AI を起こす」案を調べた（`docs/RUN_TO_COMPLETION.md`）。10/4 にユーザーが「ChatGPT でも同じ使い勝手でなければ作る価値はない」として、今のまま（作らない）に決めた | `docs/STAGE4_LOG.md`「続けて」のきっかけは今のまま |

## 2. Code タブでは何が違うか

| | チャット・Cowork | Code タブ（ローカルのセッション） |
|---|---|---|
| 待ってから続ける | できない（道具1回 約60秒まで） | **できる**。待つコマンドを裏で走らせると、Claude はいったん止まり、コマンドが終わると知らせが来て続きを始める |
| 待っている間の利用枠 | — | 使わない（AI は止まっている）。起こされたとき、会話を読み直す1回分だけ使う |
| 設定 | Claude デスクトップの設定ファイル（いまアプリが道具を1行足しているもの） | **CLI と同じ設定ファイル**（`~/.claude/settings.json` など）。道具（MCP）は設定ファイルで足せる。個人の手順書（スキル）は `~/.claude/skills/` から読む |
| アプリを閉じたら | — | ローカルのセッションは、**アプリが開いている間だけ**動く。クラウドのセッションは閉じても続くが、Mac の中の道具（UGC Analyzer）は使えない |
| 必要なプラン | Pro 以上 | 同じ（Claude Code は Pro・Max に含まれる。枠も共有） |

出典（2026-10-06 に確かめた公式の説明）:
[Code タブ（デスクトップ）](https://code.claude.com/docs/en/desktop)（同じ設定ファイルを読む・MCP を設定ファイルで足せる・`~/.claude/skills/`・裏の作業の一覧・クラウドのセッション）、
[VS Code](https://code.claude.com/docs/en/vs-code)（「裏の作業として走り続け、終わると Claude に知らせる」）、
[対話モード](https://code.claude.com/docs/en/interactive-mode)（裏で走らせるコマンド）

### 2-1. 実績（同じ日の事例で、運営の Claude Code がやったこと）

事例（`output/case_kyawa_20261006/`、ページ https://claude.ai/artifact/PhDfG1qMWM2z9bMHHN2iu6 ）の取りまとめ役のセッション（VS Code の Claude Code、Max 5x・Opus 5.5・推論 Extra high）は、
アプリの取得を「待ち続けた」のではなく、裏で走らせたコマンドが終わるたびに起こし直されて続けた:

| 待ったもの | 裏で走らせたもの | 時間 |
|---|---|---|
| 利用枠が戻る時刻 | `sleep`（04:02 まで） | 約2時間10分 |
| きゃわの取得 | 1分おきに `analysis.json` を見て、終わったら抜けるスクリプト（`watch_acq.py`） | 2時間34分 |
| 掘り下げ・切り直しの取り足し | 同じスクリプト | 7分・1分 |

ただしこの事例では、Claude デスクトップの代わりの AI 役は2回着席の形のまま動き、「続けて」を送ったのは取りまとめ役（利用者役）だった。
一気通貫では、この2つを同じ Claude が1つの会話でやる。

## 3. 利用者の流れ（案）

1. 最初の1回: Claude デスクトップの Code タブを開き、作業用のフォルダを選ぶ（アプリが用意したフォルダ。中身は空でよい）
2. 一言:「UGC Analyzer で〇〇／△△を分析して。界隈の確認はいらないので、そのまま最後まで書いて」
3. Mac と Claude を開いたまま（一晩でも）。完成すると、Code タブに完成の知らせが出る
4. 直し（掘り下げ・切り直し）も一言で。取り足しの間も待ってから書き直す

**界隈の確認**: 一気通貫で確認を聞くと、利用者が戻るまでそこで止まる。0.5.8 の「界隈の確認を省く」（`skip_confirm`）を、この形の既定にする案（7 章で決める）。

## 4. 作るもの

| # | もの | 中身 |
|---|---|---|
| C1 | 待つ命令 | `UGC Analyzer --wait <分析>`: 取得（または掘り下げ・切り直しの取り足し）が終わるか止まるまで待ち、結果を1行出して終わる（終わり方で 0＝終わった／1＝止まった／2＝ログイン待ち など）。1分おきに見る。上限あり（例: 16時間） |
| C2 | Code タブへのつなぎ | アプリが CLI と同じ設定ファイルに、道具（MCP）と許可（道具と C1 だけ）を足す。控えを取る。いまの「Claude につなぐ」（`collector/collector_app/claude_link.py`）・ChatGPT（`codex_link.py`）と同じ作り |
| C3 | 手順書（スキル） | `~/.claude/skills/ugc-analyzer/`: 名指しの決まり／kind が wait なら C1 を裏で走らせて止まる／知らせが来たら next_task を続ける／界隈の確認の扱い |
| C4 | 道具の返事 | wait の返事に、Code タブ向けの一文（「C1 を裏で走らせ、終わったら next_task を続ける」）。どの AI から呼ばれたかは、道具の初期化のときに AI が名乗る名前で分ける。チャット・Cowork・ChatGPT には、いまの一文（利用者に「続けて」を頼む）のまま |
| C5 | 眠らせない | いまは取得の間だけ Mac を眠らせない。一気通貫では、AI が書く間（30分前後）も眠らせない |

## 5. 気になる点

- **画面が開発者向け**: Code タブはフォルダを選び、許可を聞いてくる。友達の IT リテラシーでは、最初の設定の手間が増える
- **許可**: 既定のモードでは、道具やコマンドのたびに許可を聞かれる。アプリが許可の設定（道具と C1 だけ）を足して減らす。何でも通すモードを勧めるのは避ける
- **開いたまま**: ローカルのセッションは、アプリを閉じると止まる。Mac が眠っても止まる（C5）
- **利用枠**: 5時間枠に当たると止まり、戻ってから手で「続けて」が要る。Pro だと第1版だけで5時間枠の約6割を使う見込み（運営の環境 Max 5x・Opus 5.5・Extra high からの換算、事例のページ）。一晩で直しまで進めると枠を超える
- **ChatGPT**: 10/4 の決定（ChatGPT でも揃わなければ作らない）にかかる。ChatGPT の Mac アプリの Codex の画面に、同じ「裏の処理が終わったら起こし直す」仕組みがあるかは未確認（R4）
- **規約**: 利用者本人が Code タブで頼む形は、ふつうの使い方。アプリのほうから Claude を起こす形（`claude -p` など）は取らない（`docs/AI_ACCESS_UX.md` の Agent SDK の記述）

## 6. 実機で確かめること

| # | 確かめること | 分かれ目 |
|---|---|---|
| R1 | Code タブ（ローカル）で、裏のコマンドが終わったときに起こし直されるか。2〜3時間の待ちで切れないか | 駄目なら、Code タブの手元の定期実行（最短1分）で見に来る形に切り替える |
| R2 | アプリが足した設定（道具・許可・スキル）を Code タブが読むか。許可を何回聞かれるか | 聞かれる回数が多ければ、許可の書き方を直す |
| R3 | Pro で、一言から完成までの枠の増え方 | 友達に勧めるプラン |
| R4 | ChatGPT の Codex の画面で、同じことができるか | 両対応の成否（7 章） |
| R5 | 友達の手で、最初の設定（フォルダ・許可）ができるか | 友達に勧めるか、運営と慣れた人だけの選択肢にするか |

## 7. 決めること（ユーザー）

- Code タブの形を友達に勧めるか、運営と慣れた人だけの選択肢にするか
- この形では、界隈の確認を省くのを既定にするか
- ChatGPT で揃わなくても作るか（10/4 の決定の見直し）
