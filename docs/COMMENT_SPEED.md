## 1. 時間の内訳（シルエット本番 a20260930-2342-0035、193本・627分）

要求の記録（`fetch_log/comments_summary.json` の `requests`。送った時刻・cursor・動画）を、2秒以内に飛んだものを1つのかたまりにして並べた。
開いた瞬間のかたまりの順＝`rows` の順なので、かたまりを動画に割り当てられる。

| 中身 | 時間 | 割合 |
|---|---|---|
| 決まりどおりの待ち（要求 943回 × 平均33秒。設定は平均1.8回/分） | 約390分 | 62% |
| 「60秒に2回まで」で延びた分。開く瞬間に「その動画の1ページ目」と「隣の動画の先読み」が同時に2回飛ぶので、次の要求まで70秒空く | 約93分 | 15% |
| 決まりの待ちを超えた空き | 約145分 | 23% |

空きの正体:
- **続きが無い（has_more=0）と分かっている動画でも、最低20件に届かないと底で約75秒粘る。** シルエットで41本、粘って増えた動画は0本
- **待ちが明けてからスクロールを始めるので、1ページ約8秒遅れる**（ページ送りの間隔の中央値41秒 = 待ち33秒 + 8秒）

無駄な要求: 943回のうち、取らない動画への先読み 130回、開いた動画の1ページ目の取り直し 32回（計17%）。
実際の平均は毎分1.50回で、設定の1.8回にも届いていなかった。

模擬（待ちの決まりを再現して走らせ直す。TikTok には触らない）は、今のままで実績の3走行を±3%で再現した
（シルエット 628分/実績627〜630分、きゃわぽっぴんどぅー1ページ目 382/390、2ページ目 220/216）。

### 試験で見つかったこと

1. **取る予定の動画への先読みを止めると、その動画を開いても0件のままになることがある。**
   8本目を開いている間にページが9本目の1ページ目を先読みし、フックが失敗として止めた。9本目を開いてもページは取り直さず、開き直しても0件だった
   （同じように止めた3本目・7本目は取り直された。いつも起きるわけではない）。
   → 止めるのは取る予定の無い動画だけにした（`window.__capAllow`）。取る予定の動画への先読みは今までどおり通す
2. **アプリは、取得していない間に最小化された取得用 Chrome（ポート9250）を90秒で閉じる**（`collector_app/app.py` の `CHROME_IDLE_QUIT`）。
   アプリの外から試験するときは、同じプロファイルで別のポート（9251）に起こす。アプリは9250しか見ない。試験の台本は終わりに自分で閉じる
3. 最小化した Chrome の描画の確認は「0.8秒に1フレーム」になるが、前回の本番（頭打ち0）も同じなので問題ない

### 取る量を減らす（「最小のコメントで今と同じ点数のレポート」）

コメントのレポートでの使われ方（2026-10-05 の下調べ。根拠は `flow_w1.py`・`analysis/prompts/eval_rubric.md`・`docs/EVAL_SILHOUETTE_W1.md`）:
- 界隈ごとの分析で AI に見えるのは、ほとんどの動画で**いいね上位8件だけ**。全件を読むのは界隈ごとに2〜4本（シルエット 192本中45本、きゃわ 159本中32本）
- 引用されたコメントは シルエット105件（47本から）・きゃわ76件（32本から）。**返信を開いて取った返信の引用は0件**
- 今の本番レポートの点数は、まだ正式に付けていない（シルエットはユーザーの「いいレポート」という感想だけ。きゃわは正解の記事が無い）

模擬（A+B+C を入れた前提、シルエット規模）:

| 取る量 | 時間 | 要求 |
|---|---|---|
| 今の量 | 7.3時間 | 813回 |
| 返信を開かない | 5.7時間 | 609回 |
| 標準40→20件（1ページ） | 6.0時間 | 560回 |
| 標準20件・返信なし | 4.4時間 | 356回 |
| 標準20件・上限120→40件・返信なし | 3.4時間 | 253回 |

手元のデータでの机上の当たり（AI は使っていない）: 標準20件にしても「いいね上位8件」が変わらない動画は 80〜85%、
引用されたコメントが残るのは 72%（40件で 86〜89%、60件で 91〜97%）。

実験の叩き台:
1. **物差しを決める**: 今の本番レポートを採点する（シルエットは記事 No.40 の11項目と8観点。両曲共通で「構成案の主張が削った版にも立つか」）。
   同じデータで2回回し直して、回ごとのぶれを測る。削った版の差がぶれの内側なら「同点」
2. **削った版を作る**: 取得済みの `raw/comments.jsonl` を削る（取得順＝上位リスト順なので先頭から切ればよい）。界隈・ラベル・段階は元のまま固定して、コメント分析から先だけ回し直す
   （今の `reset` は全部戻すので、「plan の直後に戻す」小さな道具が要る。`prep_comments.py` の `--no-replies` は同梱の返信まで消すので1行直す）
3. **削る順**（効きが大きく、点数への影響が小さそうな順）: 返信を開かない → 上限120件の対象を絞る（本人の大量投稿は40件に） → 標準を20件に → 本数を減らす
4. 1回あたり AI の作業 約16〜22分（記録の実測）。合計16〜18回の見込み（推測）
