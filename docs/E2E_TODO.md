# 本番で E2E を使えるようにするための実装項目（2026-09-30）

> **同日の更新**: 方式は `docs/BLUEPRINT.md`（2回着席方式）に決まり、実装は `docs/IMPLEMENTATION_HANDOVER.md` の段1〜5で進める。
> この文書は実装項目の一覧として使う。**第3章の順番と D2 の説明（Codex、プラグインで接続を足す等）は古い**。
> **利用者向けの画面 E1〜E4 は作らない**（進み具合は会話、確認は会話の中、直しは会話、成果物はリンク）。指示の編集は会話で、保存はサービス（引き継ぎ書 第1-2節）。

## ゴール

**利用者が本番の Web サービス（Windows 機、公開 URL）にログインし、楽曲を指定すると、自分の AI を使って、E2E 試験と同じ品質のレポートまで受け取れる。**

E2E 試験（2026-09-12〜14）は、出来上がりのイメージを掴むために、本番とは違う形（Mac 上で Claude Code が手でつないだ）で通したもの。
レポートの品質はそこで確認できた。ここでは、**試験で人手・手作業・Mac に頼っていた部分を、本番で利用者が自分で回せる形にする**ための実装を洗い出す。

手順の全体は `docs/W1_WORKFLOW.md`（S0〜S15、確認点は H1 界隈分類のみ＋完成後の修正 H5）。

### D. AI の工程（利用者自身の Claude・ChatGPT で回す）

| # | 項目 | 内容 |
|---|---|---|
| D1 | AI の工程の受け渡し | 「サービスが指示書と入力を用意 → 利用者の AI が取りに来て、出力を返す → サービスが検査して取り込む」。どの経路でもこの形 |
| D2 | 利用者の AI とのつなぎ方（詳細は `docs/AI_ACCESS_UX.md`） | 利用者は**公式の AI アプリを入れてログインするだけ**: Claude なら Claude デスクトップアプリ（Claude Code が画面操作で使える）、ChatGPT なら ChatGPT デスクトップアプリ／Codex。そこに**サービスの接続（MCP サーバー）を1回だけ追加**する（Claude は「＋」→ プラグインで追加、Codex は「Integrations → MCP servers」で URL を追加し、サービスにログイン）。あとは作業を進めたいときにアプリで決まった一言を打つと、AI がサービスから仕事を取り、片付けて返す。**サービス側は利用者の AI のログイン情報を持たない**（Anthropic は、承認なしに第三者のサービスが claude.ai のログインを使わせることを認めていない） |
| D3 | 仕事の分割 | 1回の受け渡しが AI に収まる大きさに切る。ラベル付けは数十本ずつ、コメント分析は動画1本ずつ、執筆は章ごと。**コメント分析だけで数十〜240回の仕事になる**ので、チャットに1回ずつ頼む形ではなく、アプリの AI が仕事を順に取って片付け続ける形にする |
| D4 | 出力の検査と差し戻し | 決まった形になっているか（軸の JSON、ラベルの列、コメント ID の実在）を検査し、だめなら理由をつけて AI に返す |
| D5 | 指示書の汎用化 | 今の指示書5本には、シルエットの曲名、試験の禁止事項、`output/trial_silhouette/` のパスが埋め込まれている。対象と入力を差し込む形にし、試験の条件は外す。使った指示書は分析フォルダに写して残す |
| D6 | 知識ベースの置き場 | 著者の記事の蒸留（約10万字）と記事本文を Win に置き、執筆の仕事に添える。対象楽曲に触れる記事の除外を自動にする（今は手で作ったリスト）。分析には参照先の一覧だけ残す（**Q3**） |
| D7 | 利用者のプランの上限 | 利用者の AI は定額プランの利用上限の中で動く。1回の分析で上限に当たったら、仕事を途中で止めて、上限が戻ってから続きを取れるようにする（B3 の再開と同じ仕組み） |

### K. 知識ベースの更新（分析とは別の、運営側の作業）

**分析のたびに蒸留し直す必要はない。** 知識ベースは全利用者で共通の資産で、分析ごとに変わるのは「どの記事を除くか」と「どの記事を全文で添えるか」だけ。
ただし記事は増える（2026年は月2〜4本、最新は 2026-09-03）ので、**分析を始めるときに「未蒸留の記事がないか」を確かめ、あれば運営側で差分だけ蒸留する**。

今の知識ベースの作り（2026-09-12）:

| 部品 | 作り方 | 記事が増えたとき |
|---|---|---|
| 記事本文（89本、2021-12〜2026-09-03） | note から取得。**取得したスクリプトはリポジトリに無い**（前のセッションでその場で取った）。2本は有料で無料部分のみ | 新しい記事だけ取ればよい |
| カード（1記事1行） | 4部に分けて並行で抽出 → 統合 | **新しい記事の分だけ足せばよい**（記事ごとに独立） |
| 用語集（4万字上限）・文体ガイド（1.2万字上限） | 全記事を横断して統合し、上限に収まるよう畳んだもの | **足すだけでは済まない。** 今の版を読み直して書き換える統合が要る |
| 除外リスト（`ALLOWED.txt`） | **シルエットに触れる7本を除いた82本で作った**（答えを見ない試験のため） | 本番用には全記事の版が要る（下の K5） |

| # | 項目 | 内容 |
|---|---|---|
| K1 | 記事一覧の確認 | note の記事一覧を取り、手元の一覧と比べて、新しい記事・書き換わった記事・消えた記事を出す。数秒で終わるので、**分析を作るたびに自動で走らせる** |
| K2 | 記事本文の取得 | 新しい記事だけ取る。取得スクリプトをリポジトリに置く |
| K3 | 差分の蒸留（カード） | 新しい記事1本ごとに、カード1行と用語・文体の候補を AI が書く。小さな仕事 |
| K4 | 統合（用語集・文体ガイド） | 今の用語集・文体ガイドに候補を反映して書き直す。重いので、**新しい記事が数本たまったら**（または月1回）行う |
| K5 | 版の管理 | 知識ベースに版（日付と記事数）を付ける。分析は「どの版を見たか」を記録する（参照先の一覧、決定済み）。**本番用＝全記事の版**と、**試験用＝対象の楽曲に触れる記事を除いた版**を分けて持つ |
| K6 | 誰の AI で回すか | 全利用者で共通の資産なので、各利用者の AI ではなく**運営（Claude Code）が回す**。K1 で差分が見つかったら運営に知らせ、分析は今ある最新版で先に進める（蒸留を待たない） |
