# 0.8.0 の計画 — 頼まれたやり直しに応える・取れて当然の情報を出す・更新の手順（2026-10-12）

## 0. きっかけ

0.7.5 を友達に配ったら「やっぱり自己紹介音源は取れないみたい」と来た。会話の記録を読むと、次のことが重なっていた。

- 友達のきゃわは 10/6 に 0.6.4 で取得済み（公式の2ページだけ）・レポート未完成。新しい版の取り方は新しい取得にしか効かない
- 取り直す道が無かった。start_analysis は取得済み・未完成の同じ曲に戻し、restart_analysis・cancel_analysis は取得済みを断る（輪になる）。
  曲名を変えても、公式のページが重なるので前の分析に戻された
- アプリを入れ替えても、Claude が起こした道具の処理は 0.6.4 のまま動いていた（開き直すまで）。入れ替えの案内に開き直しが無い
- Claude が道具で答えられず、Bash で中を覗いて「60秒の音源に入っている可能性が高い」と推測で答えた。できない取り直しを「します」と言い、
  想定どおりのログの一行（Notifications are not allowed）を読み違えて、できない通知の設定を案内した
- 0.7.5 の通し試験は、取得済みのきゃわを手で脇へ移してから始めていた（この行き止まりを知っていて避けて通った）

## 1. 方針（ユーザー 2026-10-12）

1. **原理上できる頼みは断らない。** 時間がかかるなら、見込みを一度伝えてからやる（時間を理由に勝手に切らない）
2. **取れて当然の情報は道具で取れる。** AI に推測で答えさせない
3. **更新のときの文書を整える。** 今は初回のインストールの文書しかない
4. **試験・点検は運営の側でやり切る**（ユーザーに聞かない）
5. 「取り直せます」とわざわざ伝えなくてよい。ただし「最初からやって」と言われたら取り直す
6. 前の結果は消さずに残す
7. 初回の利用者は一度つまずくと戻ってこない。友達と同じ状態で確かめてから出す

通知（C）は問題ではなかった（運営の Mac でも同じ一行が出て、スクリプトエディタ名義で届いている）。直すのは AI の読み違え（第3章）。

## 2. やり直しの道具（A）

線の引き方: **TikTok に取りに行くやり直し（時間単位の待ち）** と、**集めたデータで AI だけやり直す（分単位・待ちなし）** の2系統。
どちらも前の結果は残し、時間がかかるときは見込み（時間・利用枠）を一度伝えて、そのまま進める。確かめの関所は足さない。

### 2-1. 取得のやり直し（restart_analysis を広げる。名前はそのまま）

- **どの状態でも受ける**: 取得中・順番待ち・止まった・やめた（今と同じ）に、取得済み（未完成・完成済み）を足す
- **新しい分析として取り直し、前の分析は「取り直した」の印を付けて丸ごと残す**（前のレポートもそのまま読める）。
  曲名での引き当て・「分析して」の再開は、印の付いた分析を見ない
- 前の分析の取得済みのものは、使えるときは使い回す（属性・コメント・サムネは video_id で続きから取る作りなので、重なる動画は取り直さない）
- 頼みと動き:

| 頼み（例） | 引数 | 取得 | 使い回すもの |
|---|---|---|---|
| 最初から取り直して | なし | 楽曲ページ探し・ファンの音源探しから全部 | なし（最新の数字で取る） |
| このページ（ファンの音源）も足して | add_music_urls | 一覧（全ページ）から | 属性・コメント・サムネ |
| このページは外して | remove_music_urls | 一覧から（TikTok は外さないページだけ） | 属性・コメント・サムネ |
| ファンの音源も探して／探さないで | fan_sounds | ファンの音源探しから | 属性・コメント・サムネ |
| もっと多くの動画を詳しく読んで | read_more（本数か all） | 一覧から | 属性・コメント・サムネ |
| 新しい投稿も入れて・最新の数字で | refresh | 一覧から | コメント |
| 再生の下限を〇万に | min_plays | 一覧から | 属性・コメント・サムネ |
| 返信も取って | replies | 一覧から | 属性・サムネ（コメントは返信つきで取り直す） |
| 止まった取得を続きから | resume | 止まった段から（同じ分析） | 全部 |

- 返事: どの楽曲ページで・何が変わるか・終わる見込み（取得と、そのあとの AI の作業と利用枠）を一度伝えて止まる（今の取得と同じ）
- start_analysis で同じ曲を頼まれたとき:
  - 何も違わなければ、今までどおり集め終わった分析から書き始める（「取り直せます」とは言わない）
  - **「最初から」と頼まれたら取り直す**（start_analysis に fresh を足す。全体の指示に「最初から・やり直し・取り直し は fresh／restart_analysis」）
  - 違う楽曲ページ・返信・再生の下限を頼まれたら、黙って捨てずに取り直す（上の表と同じ）
  - 前のレポートが完成している曲は、新しく取ることを一言添える
- cancel_analysis: 掘り下げ・切り直しの取り足しもやめられるようにする（今は一覧に出すのに、呼ぶと断る不具合）
- 頼める分析の数（今は取得中・順番待ち2件まで）: 断らずに順番に並べ、見込みを伝える
- 利用者が渡した楽曲ページを6つで切らない（返事は「全部」と言っている）

### 2-2. AI の段のやり直し（新しい道具 redo）

- 「〇〇からやり直して」に応える。**完成の前でも後でも使える**
- from: 界隈の案（axes）／界隈の確認（confirm）／ラベル（label）／段階（phases）／コメント分析（ccomments）／参考記事（refs）／ウェブの調べ（research）／
  時代背景（era）／構成（outline）／本文（write。章を指定できる）／note 用の仕上げ（finish）。instruction に利用者の言葉
- 動き: 今の版（outputs と仕事の状態）を history/redo_r<n>/ に残す → 段ごとの「消す表」で from から後ろを消す → from から後ろの仕事を積み直す →
  見込み（AI の作業 約N分・Pro の枠 約M割。前の分析の実測から）を伝えて、そのまま next_task へ
- 今ある部品を使う: keep_version・切り直しの RECUT_CLEAR の表・service_plan の使い回し（参考記事・ウェブの調べ・時代背景は、頼まれない限り使い回す）
- 前の版に戻す（restore）・前の版を見る（info）も付ける
- **レポートのフォルダの前の版を残す**（今は掘り下げ・切り直しで上書き）。新しい版を置くとき、前の版を「前の版/第N版」へ移す

### 2-3. いま断っている・黙って絞っているもの（調べた全部から、方針に合わせて直すもの）

| 今 | 直し |
|---|---|
| 直し（revise）は完成してから・1章だけ | 完成前の頼みは積んで完成のあとに当てる。複数章・全章も受ける |
| 掘り下げ・切り直しは完成してから・互いの途中は断る | 完成前でも受ける（積む）。途中の頼みは順に積む |
| 掘り下げの取り足しは約25分で切る（10/6 の決定） | **切らずに全部取る。見込みを一度伝える**（今回の方針に合わせる。切り直しは前から時間で削らない） |
| 界隈の確認を省く頼みは取り消せない | skip_confirm=false で戻せる |
| 利用者の頼みでも、界隈20まで・段階2〜6などの検査で差し戻す | 利用者が数を頼んだときは通す |
| 指示・設定の字数（2000字・400字） | 広げる（2000字 → 8000字、400字 → 2000字） |
| 外したファンの音源（3割に届かなかったもの）が見えない | info で見える。「それも入れて」で足せる（2-1） |
| URL を渡した取り直しで、ファンの音源探しが黙って止まる | 前の分析の指定を引き継ぐ |

今回やらないもの: 章の数・章立てそのものを変える（構成の型が固定。設計から変わるので別に考える）。
頼まれたら、できる範囲（revise で章の中身を変える）を伝える。

## 3. 取れて当然の情報（D）

### 3-1. 読むだけの道具 info（新しく）

- about: overview（楽曲ページ・外したページと理由・本数・コメント・設定・取得の日時と版・AI の進み）／sounds（音源ごとの長さ・本数、
  ファンの音源を探したか・見つけたもの・入れたもの・外したもの）／video（URL か番号で、台帳にあるか・詳しく読んだか・コメントの件数・界隈）／
  report（版の一覧・検算・確認メモ・界隈ごとの本数・ウェブ検索）／app（アプリの版・道具の版・ずれ・TikTok のログイン・取得用の Chrome・最近のエラーの要約・通知の出し方）
- **記録が無いときは理由まで言う**（例:「この分析はファンの音源を探していない（0.6.7 より前の取得）」）
- 足すデータ: 分析の目録に取得した版（app_version）、受け付けのときに外した楽曲ページとその理由（raw/page_choice.json）

### 3-2. status・read の直し

- status: 一覧に作った日・楽曲ページの数・取得した版。完成した分析にも楽曲ページを出す。同じ曲が複数あっても見分けられる形に
- read: 知らない名前には読める名前の一覧を返す。章の名前の一覧。glossary の不具合（呼び直しても直らないエラー）を直す。
  付録・確認メモ・検算・前の版を読めるように
- 道具の版（MCP の serverInfo.version）を本当の版に

### 3-3. AI への全体の指示（道具の案内・ChatGPT のスキル・Code タブの CLAUDE.md の3か所）

- 分析やアプリについての質問には、まず info で確かめてから答える。記録に無いことは「記録に無い」と言い、推測で埋めない
- アプリのフォルダやログを Bash などで直接開かない（ログの英語のエラー文には想定どおりのものがある）。設定の案内は道具の返事にあるものだけ
- 道具が断ったことを、言い換えて繰り返し呼ばない。できないことを「します」と言わない。データのフォルダを消す・動かす案を出さない
- 「最初から」「やり直し」「取り直し」「〇〇からやり直して」の頼みは、restart_analysis・redo で応える

### 3-4. 版のずれ

開き直さないと実害がある（調べで確かめた）: 前の版の道具が新しい版の分析を書くと、音源ごとの材料が消え、付録の本数が違って出る。
.app を置き換えると、前の版の道具は部品を読めずに「サービス側のエラー、呼び直して」を返し続ける（PyInstaller の部品の読み方。小さなアプリで再現）。

- 道具の処理: 起動のときに実行ファイルの印（stat）を覚え、途中で読む部品を先に読んでおく。道具が呼ばれるたびに比べ、変わっていれば仕事をせずに
  「UGC Analyzer が新しくなりました。Claude（ChatGPT）を終了（⌘Q）して開き直してください。会話と分析は消えません」とだけ返す（0.8.0 から先の入れ替えに効く）
- メニューバーのアプリ: 新しい版を初めて開いたとき、前の版の道具が動いていれば、窓で知らせて「開き直す」のボタン（0.6.6 の自動の開き直しを使う）。
  0.7.5 → 0.8.0 の入れ替えは前の版の道具が気づけないので、ここと文書（第4章）で受ける
- status・info に「UGC Analyzer の版」の1行
- 通知のログの書き方を直す（「通知センターは使えない（署名なしのため。想定どおり）→ スクリプトエディタ名義で出す」と、出したことを1行）

## 4. 更新のときの文書（B）

- 始め方のページに節「新しい版にするとき」を足す（友達に渡すリンクは1つのまま）。紙（FRIEND_GUIDE.md）も同じ
  - 始める前に: メニューの1行目が「取得中」「取り足し中」なら、終わってから
  - 入れ替えの手順（メニューから終了 → 同じリンクからダウンロード → 置き換え。「両方とも残す」は押さない → 開く）
  - **Claude（ChatGPT）を ⌘Q で終了して開き直す**（新しい UGC Analyzer を開いたあとで。これをしないと前の版のまま動き、エラーが続くことがある）
  - 確かめる: メニューのいちばん下の版の番号
  - 進めていた分析はどうなるか（そのまま続きから。新しい版の取り方で取り直したいときは「〇〇を最初から分析し直して」）
  - 困ったとき（「サービス側のエラー」が続く → 開き直す、など）
- LINE の文面の第4章を、このページの節へのリンクと、開き直しの一言に書き直す
- 版を出すときの運営の点検表（第5章の場面を通したか・文書を直したか）

## 6. これから起きそうな問題（先回り）

調べた18件から、見込みと影響の大きいものを 0.8.0 で直す。

| 問題 | 直し |
|---|---|
| 同名の曲（アーティスト違い）が前の分析に吸われる・取得中の別の曲を「受け付け済み」と返す（再現した） | 同じ曲の判定でアーティストも比べる |
| 2曲を並べて、曲名なしで「続けて」と言うと、取得中のほうを選んで「待って」と返す | 書ける分析を先に選ぶ |
| 利用者が直した指示書に、新しい版の指示が入らない（知らせも無い） | 版を上げたときに、直した指示書があれば info・完了の知らせで伝える |
| 古い分析が溜まる（1つ 144〜443MB。しまう・消す道具が無い。一覧が長くなり、曲名の取り違えも増える） | 分析をしまう（あとで戻せる）道具。status の一覧はしまったものを出さない |
| 同じ日・同じ題でレポートのフォルダが重なり上書き | フォルダ名に分析の短い印を足す（2-2 の前の版を残すのと合わせる） |
| 知識ベースの同梱物が、版を上げても既存の Mac に届かない（用語集・文体ガイドなど） | 版を上げたときに、運営の同梱物は入れ替える（Mac で足した分は残す） |
| 「両方とも残す」で2つ目の .app ができる | アプリが気づいて知らせる |
| ディスクの空きを見ていない | 取得の前に確かめ、足りなければ始める前に伝える |
| 掘り下げの最初の返事の「続けて高校生の界隈も頼みます」が、次の会話に引き継がれない | 2-3 の「積む」で、頼みを分析の側に残す |

様子を見るもの（直さない）: 利用枠の上限で途中で止まる（渡し直しは今も効く。目安は文書にある）、TikTok に止められる・ログインが切れる（今の扱いで足りている）、スリープ（続きから進む）。
