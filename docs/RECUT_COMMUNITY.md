# 界隈の切り直し（完成後に、界隈の分け方を変えてレポートを書き直す）— 設計と作業記録（2026-10-06〜）

## 0. 一言で

レポートが完成したあと、利用者が「〇〇界隈を2つに分けて」「△△と□□をまとめて」「動機で切り直して」のように**界隈の分け方そのもの**を変えたいと言ったら、
**利用者の指示どおりに界隈を切り直し、動画のラベルを付け直し、新しい界隈で読むべき動画にコメントが無ければ取り足してから、レポートを新しい版に書き直す**。

- 道具 `recut(instruction)`。instruction は利用者の言葉そのまま
- 前の版は消さない（`outputs/history/recut_r<回>/`）
- 「ある界隈の話が浅い」は掘り下げ（`deepen`、`docs/DEEPEN_COMMUNITY.md`）、章の言い回しや考察の足しは直し（`revise`）

## 1. 決まったこと（2026-10-06 ユーザー）

| # | 問い | 答え |
|---|---|---|
| 1 | 何をやり直すか | 界隈の切り直しから。利用者の指示を十分に尊重して界隈を切り直し、動画にラベルを付け直す |
| 2 | コメントが足りるかの決め方 | 第1版の取得の基準（再生上位・公式や認証かどうか）を、新しい界隈に当てはめる（下の 3 章） |
| 3 | 足りるとき・足りないとき | 足りていれば、そのまま執筆の流れを最後まで（**着席1回**）。足りなければ、足りるまで取ってから執筆（**着席2回**） |
| 4 | 追加の頼みが要るとき | 「レポートの直しが終わるまでに追加の頼みが要るときは、**最初に**利用者に伝える」。足りるかはラベルを付け直さないと分からないので、付け直した直後（AI の最初の返事）で止まって、何分後に戻るかを事情と共に伝える（`come_back_line`、`docs/DEEPEN_COMMUNITY.md` 3-1） |

確認の関所は足さない（利用者に「この分け方でいい？」と聞かない）。どう切り直したかは、止まったときの返事か完了の知らせで伝わる。

## 2. 利用者の流れ

1. 利用者「〇〇のレポート、ダンスの界隈を屋外の人と室内の人に分けて」
2. AI が道具 `recut` を呼ぶ → 最初に一言「界隈を切り直して、動画のラベルを付け直します。新しい界隈でコメントが足りないときは、付け直したところで一度止まり、何分後に戻ればよいかをお伝えします。足りていれば、そのままレポートの新しい版まで進めます。」
3. AI が `next_task` で、分類軸の直し（仕事 `recut`）→ ラベルの付け直し（`label`×）を片付ける
4. サービスが足りるかを確かめる（`recut_check`）
   - **足りる** → AI はそのまま段階 → 界隈ごとのコメント分析 → 構成案 → 執筆 → 仕上げ → 完了（新しい版）。着席1回
   - **足りない** → Mac が取り足しを始め、AI はその場で止まる。返事の最後に、言い換えずにこの一文:
     「切り直した界隈のコメントを集めるのに約〇分かかります（〇時〇分ごろに終わる見込み）。その間 AI は待てないため、Mac に通知が出たら『〇〇の分析を続けて』と頼んでください。新しい界隈の分け方でレポートを書き直します。」
     → 通知 → 利用者「〇〇の分析を続けて」→ 段階から先、完了まで。着席2回

## 3. コメントが足りるかの決め方（`acquire/recut.py` の `RULE`・`plan`）

第1版の取得（`analysis/pool.py`、仕様は `docs/COMMENT_TARGETS.md`）は界隈が決まる前に動くので、起点・大型ヒット・認証アカウント・本人・公式は**曲全体**で数え、
それに「属性の山ごとの再生上位3本」を足している。切り直しでは、同じ考え方を**新しい界隈の中**に当てはめる:

| 区分 | 界隈の中での選び方 |
|---|---|
| 再生上位 | その界隈の再生上位3本 |
| 最初期 | その界隈で最初に下限を超えた投稿1本（その界隈の入口） |
| 認証 | その界隈の認証アカウントの再生最上位1本・最初期1本 |

- どれも**再生の下限**（その分析の週ごとの下限 `min_plays_weekly`、既定10万）以上から選ぶ
- 選んだ動画（必ず読みたい動画）に**コメントがあれば足りる**。無ければ取り足す。前に「動画が無い・コメントが無い・開けない」だった動画と、楽曲ページの一覧で見つからなかった動画は、取りに行っても取れないので外す
- **確かめるのは、切り直しで動画の顔ぶれが変わった界隈だけ**（`RULE["scope"]="changed"`）。変わっていない界隈は第1版と同じ材料で書けている。`"all"` にすると全部の界隈を確かめる
- 取り方は本線に合わせる: 1本1ページ（`pool.CAP_PAGE`＝20件）、見込みは `pipeline.minutes_per_comment_video`（1ページなら0.7分、推測）＋楽曲ページ1つにつき準備 `deepen.EST["page_min"]`（6分）。時間では削らない（足りるまで取る）

本番2曲の**今の界隈**に全部の界隈で当てはめた試算（`python -m acquire.recut plan <分析フォルダ>`、AI なし。2曲とも前の取り方〔120件・40件〕で取った分析）:

| | 必ず読みたい動画のうちコメントが無い | 取り足しの見込み |
|---|---|---|
| シルエット | 6本（14界隈中5界隈） | 約10分 |
| きゃわ | 10本（12界隈中7界隈） | 約19分 |

1ページの取り方（0.5.4〜）で取った分析では、コメントのある動画が減るので本数は増える（属性の山の上位を足す前の試算で約20本ずつ）。
実際の切り直しでは顔ぶれが変わった界隈だけを確かめるので、これより少ない。

## 4. AI の仕事とサービスの工程（`flow_w1.py`）

道具 `recut` は仕事 `recut` を末尾に足すだけ。受け付けたら（`accept_recut`）:

1. 前の版を `outputs/history/recut_r<回>/` に写す（prompts・history は除く）
2. 作り直すもの（labels/・synthesis/・chapters/・note_chapters/・labels.tsv・phases.json・pathway.md・outline・REPORT.md・NOTE_BODY.md・EDITOR_NOTES.md・note_meta.json・verify.json）を片付ける。
   参考記事（references/）・直しの記録（revisions/）・Excel 用 ZIP は残す
3. 新しい分類軸を taxonomy.json に。`keep`（定義を変えず動画も移ってこない界隈。key の付け替え・そのままの合併もできる）の動画は前のラベルのまま `labels/batch_00.tsv` に
4. 残りの動画（ラベル対象のうち keep 以外）を30本ずつ付け直す仕事を足し、続けて `recut_check`［サービス］→ `phases`（段階と拡散経路の下書き）→ `plan`［サービス］を足す
5. `plan` から先はふつうの流れ（界隈ごとのコメント分析 → 構成案 → 執筆 → 組み立て → 仕上げ → 題名 → 検算 → ZIP → 完了）。参考記事の章立ては界隈に依らないので使い回す

| 仕事 | 中身 |
|---|---|
| `recut`（AI） | 利用者の指示・今の界隈（本数・コメントのある動画・初出・再生上位）・今の分類軸を見て、分類軸の全体と keep と利用者への一言を返す。材料は read の `labeled:<界隈>`（その界隈の動画と今のラベル）・サムネ・`synthesis`・`chapter:<id>`・`kb:community` |
| `label`×（AI） | ふだんのラベル付けと同じ。利用者の指示を添える（前のラベルにとらわれない） |
| `recut_check`（サービス） | 前後のラベルを比べて顔ぶれが変わった界隈を出し、必ず読みたい動画にコメントが無ければ取り足しを積む（`analysis.json` の `deepen` の枠に `kind: "recut"`） |
| `write`×（AI） | ふだんの執筆に、利用者の頼み・前の版の同じ章（read の `prev:<章>`。界隈の話は写さず、利用者の考察を活かすときだけ）・前の版で利用者が頼んだ直し（revise の記録）を添える |
| `done` | 完了の知らせに「今回の直し（界隈の切り直し）」: 利用者の頼み・切り直し・新しい界隈・顔ぶれが変わった界隈・取り足し |

検査（`accept_recut`）: 分類軸の形（`check_taxonomy`）・keep の key が前後の界隈にあるか・1対1で残す界隈の定義が前と同じか（分けた界隈を keep に入れると差し戻す）・前と同じ分類軸は差し戻す。
format・motive・tier を変えたら keep は使わず全部付け直す。

## 5. 取り足し（掘り下げと同じ仕組み）

`analysis.json` の `deepen` の枠に `kind: "recut"` で積む（`acquire/recut.py` の `request`。回の数え方は掘り下げと共通）。取得の係（`acquire/worker.py`）・取る（`acquire/deepen.py` の `Run`）・
原本に合わせる（`deepen.merge`）・アプリの眠り止め・Chrome・通知は掘り下げと同じものを使う。違うのは言葉と印だけ:

- 取った行の印 `pool_reason` は `recut:r<回>:<界隈>`、コメントの整形の印は「界隈の切り直しで取り足した（<界隈>）」
- 待ちの返事・進み具合・メニュー・通知は「切り直した界隈」「界隈の切り直しの取り足し」
- 取り足しを積んだ直後の `next_task` だけ、`come_back_line` の一文つきの待ちを返す（`announced` を付けて2回目からは出さない）
