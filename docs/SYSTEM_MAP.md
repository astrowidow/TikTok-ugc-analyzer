## 1. 経路は2つ。違うのは「取得をどこでやるか」だけ

| | **本線（第一優先）** | **非常用** |
|---|---|---|
| 取得する場所 | その人の Mac の取得アプリ | 運営の Windows 機 |
| TikTok のアカウントと回線 | その人の捨て垢・その人の回線 | 運営の捨て垢・運営の家の回線 |
| 使う人 | 全員が基本これ | 取得アプリを使えない友達（会社の管理下の Mac・Intel など）と、アプリの不具合のとき |
| 取得のあとの AI の作業 | Windows 機の「サービス」が相手 | 同じ |

作るものの中心は本線。非常用は今あるものを残すだけで、新しく作るものは無い。

## 2. Windows 機には役が2つある（ここが混ざりやすい）

| 役 | 中身 | 本線で使うか |
|---|---|---|
| **サービス** | AI に指示書と資料を渡す。AI の結果を受け取って検査する。分析のデータとレポートを持つ。取得アプリから取得の結果を受け取る | **使う（1曲ごとに毎回）** |
| **取得** | Windows 機の Chrome と運営の捨て垢で TikTok から取る | **使わない（非常用だけ）** |

- **非常用なのは下の「取得」だけ。上の「サービス」は本線の一部。**
- 理由: 友達の Claude は Anthropic のクラウドで動くので、友達の Mac の中の取得アプリには届かない。
  AI が指示書をもらい、結果を返す相手は、インターネットから届く場所に置く必要がある。それが今は Windows 機のサービス
  （2026-10-01 にも「その人の PC で取得するならサーバーにつなぐ必要ないのでは？」という問いが出ている。`docs/STAGE4_LOG.md`）
- なので本線でも、Windows 機が止まっていると AI の作業と結果の受け取りは進まない。Mac の取得だけは最後まで走り、サービスが戻ったら上げ直す

## 3. 本線の流れ（1曲ぶん）

| # | 起きること | どこからどこへ | Windows 機のサービスを使うか |
|---|---|---|---|
| 1 | 友達が Claude に「〇〇を分析して」 | 友達の Claude → サービス | 使う。受け付けて、その人の Mac あての仕事にする |
| 2 | 取得アプリが仕事を受け取る | 取得アプリ → サービス | 使う |
| 3 | **取得（13時間前後）** | 取得アプリ → TikTok | **使わない。Windows 機も ngrok も通らない** |
| 4 | 取得の結果を上げる | 取得アプリ → サービス | 使う（1曲に1回） |
| 5 | 翌日「続けて」→ 界隈の確認 → レポートまで | 友達の Claude ⇔ サービス | 使う（AI が道具を約250回呼ぶ） |
| 6 | レポートを受け取る | 友達のブラウザ → サービス | 使う |

非常用の経路では、2〜4 が「Windows 機の取得の係が自分で取る」に置き換わる。1・5・6 は同じ。

```
本線:
  友達の Claude ──1・5──────────┐
  友達のブラウザ ──6────────────┼──> ngrok ──> Windows 機の「サービス」
  友達の Mac の取得アプリ ──2・4─┘
        │
        └──3 取得 ──────────────────────────────────────────> TikTok   （ngrok も Windows 機も通らない）

非常用:
  Windows 機の「取得」（運営の捨て垢）──────────────────────> TikTok
```

## 4. ngrok の位置づけ

**ngrok は、家の外から Windows 機のサービスに届くための通り道。それだけ。**

- 本線でも非常用でも、サービスに届くとき（第3章の 1・2・4・5・6）に通る。取得（3）は通らない
- 家の中からは通らない（運営が LAN から CSV 画面を使う、ssh で保守する）
- 取得アプリを作ったから ngrok が要るようになった、のではない。AI がサービスに届くために、段1（2026-09-30）から使っている

作るうえで ngrok について守ることは2つだけ:

| # | 守ること | 理由 |
|---|---|---|
| 1 | 取得アプリが数分おきにサービスに聞きに行く作りにしない（長くつないだまま待つ。だめなら30分おき） | 無料の枠（月2万リクエスト）を、待っているだけで使い切らないため。引き継ぎ書に元からある注意 |
| 2 | 外から届く口を、AI の接続口・ダウンロード・取得アプリ用の3つだけにする（決定8） | いまは外から CSV 画面にも届く。その Basic 認証の既定の値は公開リポジトリの `start.bat` に書いてある |

枠について分かっていること（設計を左右しない。運用の目安）:

- 本番のログから数えた（2026-10-03）: 1曲で約1,000リクエスト。ほとんどが第3章の5（AI の作業）で、取得アプリの分は小さい
- 4人で月8曲なら約1.5万で無料の枠に収まる。月16曲だと越えるが、月10ドルの枠（10万リクエスト）に上げれば済む
- 上げるときに固定のアドレスが変わらないかだけ、上げる前に確かめる（変わると全員の接続を入れ直すことになる）
- 数え方と内訳は第9章

## 5. 場所ごとの中身

文書と報告では、どこの話かを次の印で示す。

| 印 | 場所 | 経路 |
|---|---|---|
| **[Mac]** | 友達（と運営）の Mac の取得アプリ | 本線 |
| **[AI]** | 友達の Claude | 本線・非常用の両方 |
| **[サービス]** | Windows 機のサービス（AI の相手・データ） | 本線・非常用の両方 |
| **[受け渡し]** | 取得アプリとサービスの間のやりとり（第3章の 2・4）。両方に作るものがある | 本線 |
| **[非常用]** | Windows 機の取得（Chrome 9222・運営の捨て垢・タスク `tiktok-acq`） | 非常用 |
| **[ngrok]** | 通り道（第4章） | — |

### [Mac] 取得アプリ

| 項目 | 中身 |
|---|---|
| プログラム | `collector/`（`collector_app/`）。取得の本体は本線の `acquire/`・`analysis/` を同梱してそのまま使う |
| データ | `~/Library/Application Support/UGC Collector/`（取った原本・サムネ・記録、取得用 Chrome のプロファイル＝捨て垢のログイン） |
| すること | 取得の工程を全部（第7章）。終わったら結果をサービスに上げる |
| しないこと | AI の仕事、レポート作り。捨て垢の ID・パスをどこかに送ること |
| 配り方 | .dmg（署名なし）。作るのは運営の Mac（`collector/build.sh`） |

この場所だけで閉じる話（サービスにつながなくても試せる）:
入れ方と「このまま開く」／メニュー／Mac の通知／取得用の Chrome（最小化・閉じられたら開き直す・描画の見張り）／捨て垢のログイン／
スリープ・ふたの開け閉め・続きから／13時間の連続取得／Intel の Mac・会社の管理下の Mac。

- 確かめ済み（試作 0.1.0、`docs/COLLECTOR_TRIAL.md`・`docs/STAGE4_LOG.md`「ユーザーの試し」）: 入れる・ログインをユーザーが自分でできた／小さい規模で Windows 機と同じ質／アプリを起動し直しても取得は続く
- まだ: 本番規模の一晩（最後にユーザーが保証する）、友達ごとの Mac の環境

### [AI] 友達の Claude

- 友達がすること: 接続を1回足す（運営が LINE で渡す、その人専用の秘密の URL）。あとは決まった一言
- こちらが作るプログラムは無い（道具と指示書はサービスが出す）
- この場所だけで閉じる話: Claude のプラン（Pro 以上）／枠に当たったときの「続けて」／ChatGPT（要望が出たら）／友達向けの紙1枚

### [サービス] Windows 機のサービス

| 項目 | 中身 |
|---|---|
| プログラム | `main.py`（Web サービス、ポート 8000）／`mcp_proto.py`（AI の接続口 `/mcp/`）／`downloads.py`（ダウンロード `/dl/`）／`proto_runner.py`・`flow_w1.py`（仕事の列・指示書・検査）。**これから**: `runner_api.py`（取得アプリ用の口 `/runner/`） |
| データ | `output\analyses\<分析ID>\`（原本・記録・計算物・成果物・仕事の状態）。利用者と取得アプリの対応表は `ugc-secrets\`（リポジトリ外） |
| 置き場 | `C:\Users\astrowidow\workspace\TikTok-ugc-analyzer\`（git 管理外。触る前に控え） |

この場所だけで閉じる話: 分析をどちらの経路で取るかの振り分け／`status`・`next_task` の文面／1人1件／接続の URL を止めて出し直す／
本番に入れる手順（控え・再起動）／既存の CSV 画面を壊さない。

### [非常用] Windows 機の取得

- 今あるものをそのまま残す（`acquire/` の係、Chrome 9222、運営の捨て垢）。新しく作るものは無い
- 気をつけるのは1つ: 本線の分析を、この係が間違って拾わないようにする（拾うと運営の捨て垢で取ってしまう）

## 6. [受け渡し]: 取得アプリとサービスのやりとり（第3章の 2・4）

サービスの側から Mac に話しかける道は無い（家の外の Mac には届かない）。いつも取得アプリの側から聞きに来る。

| やりとり | [Mac] 取得アプリの側 | [サービス] の側 |
|---|---|---|
| つなぐ（最初の1回） | 6桁の番号をもらって、メニューと通知に出す | 番号を出す（15分で失効・試行に上限）。利用者が Claude で「取得アプリをつないで 482913」と言うと、AI の道具がその人とアプリを結ぶ |
| 仕事を待つ | 1本の要求をつないだまま待つ。切れたらつなぎ直す | その人あての分析ができたら、待っている要求に返す |
| 様子を送る | 取得中だけ、工程・本数・Mac の状態を送る | `analysis.json` に書いて `status` の文面に使う。長く来なければ「Mac が閉じているか、アプリが止まっています」 |
| 結果を上げる | 原本（サムネを除く）・記録・計算物を1つに固めて上げる。失敗したら上げ直す | 受け取って分析フォルダに広げ、取得済みにする |

サービスや ngrok が止まっていても取得は続け、つながったら上げ直す作りにする。

## 7. 取得の工程が、どこで動くか

| 工程 | 本線 | 非常用 |
|---|---|---|
| 楽曲ページを探す（曲名 → URL） | [Mac]（いまの作り）→ **下の「穴」** | Windows 機 |
| 動画の一覧・属性とサムネ | [Mac] | Windows 機 |
| 集計と AI の入力（サムネの一覧画像など） | [Mac] | Windows 機 |
| コメントを取る動画を決める・コメント・整形 | [Mac] | Windows 機 |
| 終わりの知らせ | [Mac] の通知 | 無し（メールはやらない） |
| 結果をサービスに渡す | [受け渡し] で上げる | 要らない（同じ機械） |
| AI の作業（2回目の着席） | [AI] と [サービス] | 同じ |

**穴（2026-10-03 に見つけた。本線の話）**: 曲名から楽曲ページを探す工程は、検索サービス（Tavily）の鍵を使う。鍵があるのは Windows 機だけ。
Mac では鍵なしの検索（DuckDuckGo）になり、Bot 判定で失敗することがある（`scraper.py` の注意書き）。
試作の2回（mosi mosi・ビジュがレベチ）はどちらも URL を渡して頼んだので、**Mac での検索は一度も動いていない**。友達は曲名で頼む。
→ 案: サービスが受け付けのとき（第3章の1）に探し、URL を付けて Mac に渡す。検索サービスを使うだけで、TikTok には触らない。
見つけた楽曲ページをその場で利用者に見せられるので、「最初に見つかったページを確かめずに使う」という既知の弱点（引き継ぎ書 第6章）も一緒に扱える。

## 8. 言葉の決まり

| 言葉 | 指すもの |
|---|---|
| 本線 | 各自の Mac の取得アプリで取る経路。第一優先 |
| 非常用 | Windows 機で、運営の捨て垢で取る経路 |
| 取得アプリ | UGC Collector（メニューバーのアプリ） |
| 取得用の Chrome | 取得アプリが開く、専用プロファイルの Chrome（ポート 9250） |
| サービス | Windows 機で動く、AI の相手とデータの置き場。**取得はしない**（Windows 機の取得は「非常用」と呼び分ける） |
| 接続口 | AI が道具を呼ぶ口（`/mcp/`） |
| 取得アプリ用の口 | 取得アプリがサービスと話す口（`/runner/`） |
| 受け渡し | 取得アプリとサービスの間のやりとり |
| 秘密の URL | 利用者1人に1つの接続の URL。運営が出して LINE で渡す |
| 6桁の番号 | 取得アプリと利用者を結ぶための、15分で切れる番号 |

「サーバー」「ランナー」「Windows 機のルート」は使わない（どちらの役か分からなくなるため）。
