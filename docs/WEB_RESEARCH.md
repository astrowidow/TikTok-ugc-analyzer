## 仕事の列

```
… ccomments× → ref_select → ref_digest× → research（ウェブで調べる）→ era（時代背景の材料）→ outline → write× → …
```

- **research**（AI、JSON）: 曲の情報（`song`）・TikTok の外の指標（`outside`、値の時点 `as_of` つき）・要のアカウントの素性（`people`）・探したが見つからなかったもの（`not_found`）。
  - 1件ごとに出どころの URL が要る（無ければ差し戻し）。数字は開いたページで確かめたものだけ、と指示書に書く
  - 要のアカウントはサービスが選んで渡す（段階の代表・見落とされがちな動画・再生上位・本人と公式のうち、認証・フォロワー10万以上・公式・大手）。調べてよいのは本人・公式・芸能人・事務所所属のタレントだけ
  - この曲のバズを分析した記事の結論は拾わない（分析は TikTok のデータから自分で出す。数字と出来事だけ拾う）
  - サービスが W1〜 の番号を付けて `outputs/research.json`・`research.md` に置く（read の `research`）
  - **ウェブ検索が使えない AI は `{"web_search": false}` で通る**。記事は TikTok の中のデータだけで書き切り（外のことには触れない）、完了の知らせと確認メモで「ウェブ検索をオンにして、6章に外の数字を足してと頼めば足せる」と一言
- **era**（AI、Markdown）: `### この曲の型`／`### 似た位置づけの曲`／`### 同じ時期の流行`／`### この曲の立ち位置`。
  - 材料はサービスが渡す: 分析の要約・使われ方（尺・画面の文字・検索候補・音に触れたコメント）・調べた曲の情報・用語集の B 章（十四分類・感情ダイレクトアタック曲・自己肯定感アップ曲など）・楽曲分析の記事の一覧（カード）・同じ時期の月報（曲の公開から分析の時点まで。足りなければ直前）
  - 出どころは記事の名前（`2025-04-03_n…`）で、一覧にあるものだけ。「似た位置づけの曲」に2本以上。分析する曲を扱った記事は使えない（`exclude_same_song`、参考記事と同じ決まり）
  - `outputs/era.md`（read の `era`）
- 界隈の切り直し（recut）のあとは、research・era を使い回す（曲の外のことは界隈に依らない）。掘り下げ（deepen）は触らない

## 書き方と検査

- 構成案: 材料に TikTok の外の指標と、時代背景の材料の結論。根拠に `{"web": "W3"}` を使える（research にある番号だけ）
- 執筆: 調べた事実を使ったら文末に `[W番号]`。材料に無い外の事実（チャート・再生数・経歴）は書かない。記事の名前を本文に書かない。
  3〜5章は 2,500〜5,000字（前は 800〜2,000字）、6〜8章は 1,500〜4,000字
- 仕上げ（note 用）: `[W番号]` を消す。YouTube の公式の動画（MV など）に触れたら、その URL をそれだけの行に置いてよい（note が埋め込みに変える）
- 検算: 根拠の番号つきの版（REPORT.md）の `[W番号]` が research にあるか
- 付録（REPORT.md）に「ウェブで調べたことの出どころ」の一覧

## 成果物の名前（利用者のフォルダ）

| 中の名前（outputs/） | 利用者のフォルダの名前 | 説明（完了の知らせ） |
|---|---|---|
| NOTE_BODY.md | レポート.md | 読む・note に貼るのはこれ（動画は埋め込みの行、根拠の番号なし） |
| REPORT.md | レポート（根拠の番号つき）.md | 同じ分析の、仕上げる前の原稿。どの動画（seq）・コメント（cid）・ウェブの出どころ（W）から言ったかの番号と、使ったデータの付録つき |
| EDITOR_NOTES.md | 確認メモ.md | ウェブで調べた数字の出どころと、推測で書いたところ（公開の前に確かめたいとき） |
| data.zip | data.zip | Excel 用のデータ |

前の名前（REPORT.md など）で同じフォルダに置いた写しは、新しい名前で置くときに消す。中の名前は変えない（検算・直し・掘り下げ・切り直しが使う）。

**2つのレポートを分けている理由**: AI は章ごとに、主張の根拠（動画の seq・コメントの cid）を添えて書く。サービスはその番号で数字を照合し（検算）、直し・掘り下げ・切り直しもこの原稿を元にする。
読者向けの版は、それを章ごとに note 向けに仕上げたもの（番号を消す・動画を埋め込みの行に・表を箇条書きに・推測を著者の口調に・7割ほどに詰める）。番号を消した版だけにすると、照合と直しができなくなる。
利用者が読むのは「レポート.md」だけでよい。

## コードを読む係（R8）の指摘と直し（2026-10-06）

d9 の通し試験で、コードを読む係 R8 が 0.6.2 の差分を読み、11件を見つけた（`tests/test_review_r8.py`）。全部直した:

- 文体ガイド（同梱の STYLE_GUIDE.md）が名乗り・一人称の「山本」「弊社」「当社」・募集・号数を勧めていて、最初の提出が差し戻されやすかった →
  read の `kb:style` の先頭に「UGC Analyzer の決まり（この文体ガイドより優先）」を付ける。`AUTHOR_RE` に「山本は」「当社」「コンサル依頼」「執筆者：」【山本の気づき】を足す
- 引用（『』「」の中）の「弊社」「山本です」まで止めていた → 検査の前に引用を外す（`QUOTED_RE`）
- ウェブ検索なしの分析で「6章に外の数字を調べて足して」と頼むと直し（revise）になり、同じ案内がまた出た → 直しでも頼まれたらウェブで調べて書いてよい
  （出どころは文中に「（出どころ: …）」）。research のあとに直しが入ったら、完了の知らせと確認メモで案内しない（`web_added_later`）
- 前の形の分析を直すと、3〜5章に「人の考察を入れる場所」が残るのに「書き切ってある」と言った → 完了の知らせの 3（`{{completeness}}`）をサービスが選ぶ
- 時代背景の材料が無い分析で、似た曲を具体的に挙げさせていた（記憶で書かせる道）→ `kb:cards` と `note:` で過去の記事を読んでから比べる。無い資料（research・era）を目録に載せない
- `web_search` の行を「[」で始まる行の前に入れていて、複数行の文字列・配列を壊すことがあった → ファイルの先頭に入れる
- 題名の号数の検査が冒頭の章の1行目を見ていなかった → 執筆・仕上げの検査でも見る（`NUMBER_RE`）
- YouTube の URL の動画 ID（v=P3_…）を内部の印と取り違えた → URL を外して検査する
- 時代背景の材料の見出しが「####」だと直し方の分からない差し戻しになった → 「###」にそろえて受け取る
- 確認メモの「推測で書いたところ」に検査が無かった → 同じ検査をかける
- 「書き足」が「本人が歌詞を書き足したと語っている」も止めた → 人が書き足す前提の言い方だけに

## 残り

- **ChatGPT（Codex）**: Work の画面（中身は Codex）のウェブ検索は既定が `cached`（OpenAI の索引だけを見る。ページを生では取りに行かない）で、YouTube の再生数のような日々変わる数字が取れない（2026-10-06 の下調べ。https://learn.chatgpt.com/codex/web-search ほか）。「ChatGPT につなぐ」（codex_link.py）が `~/.codex/config.toml` のいちばん上の階層に `web_search = "live"` を足す（利用者がすでに web_search を決めていれば触らない。つなぎを外すと消える。スキルの文が変わったので、0.6.2 を入れると起動のときにつなぎ直して足す）。Work の画面がこれを読んで live で調べるかは実機で未確認。使えなければ `web_search: false` で通る
- **Claude デスクトップ**: チャット欄の「+」→「Web search」が会話ごとの切り替え（オンならページの取得もできる）。個人プランの既定は公式に書かれていない。切れていれば `web_search: false` で通り、完了の知らせで「ウェブ検索をオンにして頼めば足せる」と一言。始め方のページで最初にオンにしてもらうかは未決
- ウェブの数字はサービスが照合できない（出どころの URL と時点を確認メモに出すだけ）
- 書く時間と利用枠の目安の見直し（調べる仕事が2つ増える）。友達向けのページ・紙は 0.6.2 を配るときに直す
