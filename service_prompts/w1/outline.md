## 指示書

{{song}} の分析記事を書く前に、**記事全体の構成案**を作る。このあと章ごとに別の仕事で書くが、全章がここで決めた主張と流れに沿って書かれる。
記事全体の論理がぶれないよう、**先に結論を決めて、各章がそれをどう支えるかを割り振る**。

### 読むもの

- 参考記事の章立てと論理の運び（read の `refs`。{{n_refs}} 本ぶん）
- 界隈ごとのコメント分析（read の `synthesis`）
- ウェブで調べたこと（read の `research`。曲の情報・TikTok の外の指標・要のアカウントの素性。項目ごとに `W番号`）と、
  時代背景の材料（read の `era`。この曲の型と、似た位置づけの曲）
- 下の材料

楽曲の特徴・切り出し箇所・時代背景（`music`）、バズった結果（`result`）、冒頭（`intro`）は、ウェブで調べたことと時代背景の材料も根拠にして、
**データから書けない部分を残さない計画**にする（人が書き足す場所を作らない）。TikTok の外の指標が見つかっていれば、記事全体の主張にも使ってよい。

音源が2つ以上あるとき（材料の「音源ごと」）は、音源（曲のどの部分を切り抜いたか）ごとに使われ方が違わないかを見る。
別の部分の音源で新しい使い方の波が起きていれば、それはこの曲が広がった理由の一部なので、記事全体の主張と、拡大経路・分岐点・切り出し箇所の章に割り振る
（なぜその部分がその使い方に向いたかまで）。違いが無ければ、どの章でも音源の違いには触れない（「別の使われ方は無かった」とも書かない）。

### 決めること

1. **記事全体の主張**（一言。「この曲はなぜ伸びたか」への答え）
2. **章ごとの計画**。章の並びと見出しは決まっている（下）。各章について:
   - その章の役割（記事全体の主張のうち、何を受け持つか）
   - 主張（1〜4個）と、それぞれの根拠（動画は seq、コメントは cid、数字は材料の値）。根拠が薄い主張は guess を true に
   - 次の章へのつなぎ（一文）
3. 記事の題名の案

読者は音楽や SNS に関わる人で、こちらの作業の仕組み（集めた動画の本数・ラベル・界隈の key・段階の ID）は知らない。
主張は「この曲の UGC 全体で何が起きたか」として立てる。集めた動画は、経路を調べるための手掛かりにすぎない。

### 出力の形（JSON 1つ）

```json
{"thesis": "記事全体の主張（一言）",
 "title_idea": "記事の題名の案",
 "chapters": [{"id": "<章の id>", "role": "この章の役割",
               "claims": [{"claim": "主張", "evidence": [{"seq": 12}, {"cid": "7534…"}, {"web": "W3"}, {"number": "UGC 約13万（楽曲ページ、取得時点）"}], "guess": false}],
               "bridge": "次の章へのつなぎ（一文）"}]}
```

- chapters は上の章の並びの id を全部、この順で
- evidence の seq・cid は、材料と `synthesis` にあるものだけ。web は `research` にある W番号だけ
