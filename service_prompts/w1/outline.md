## 指示書

{{song}} の分析記事を書く前に、**記事全体の構成案**を作る。このあと章ごとに別の仕事で書くが、全章がここで決めた主張と流れに沿って書かれる。
記事全体の論理がぶれないよう、**先に結論を決めて、各章がそれをどう支えるかを割り振る**。

### 読むもの

- 参考記事の章立てと論理の運び（read の `refs`。{{n_refs}} 本ぶん）
- 界隈ごとのコメント分析（read の `synthesis`）
- 下の材料

### 決めること

1. **記事全体の主張**（一言。「この曲はなぜ伸びたか」への答え）
2. **章ごとの計画**。章の並びと見出しは決まっている（下）。各章について:
   - その章の役割（記事全体の主張のうち、何を受け持つか）
   - 主張（1〜4個）と、それぞれの根拠（動画は seq、コメントは cid、数字は材料の値）。根拠が薄い主張は guess を true に
   - 次の章へのつなぎ（一文）
3. 記事の題名の案

読者は音楽や SNS に関わる人で、こちらの作業の仕組み（集めた動画の本数・ラベル・界隈の key・段階の ID）は知らない。
主張は「この曲の UGC 全体で何が起きたか」として立てる。集めた動画は、経路を調べるための手掛かりにすぎない。

### 出力の形（JSON 1つ）

```json
{"thesis": "記事全体の主張（一言）",
 "title_idea": "記事の題名の案",
 "chapters": [{"id": "<章の id>", "role": "この章の役割",
               "claims": [{"claim": "主張", "evidence": [{"seq": 12}, {"cid": "7534…"}, {"number": "UGC 約13万（楽曲ページ、取得時点）"}], "guess": false}],
               "bridge": "次の章へのつなぎ（一文）"}]}
```

- chapters は上の章の並びの id を全部、この順で
- evidence の seq・cid は、材料と `synthesis` にあるものだけ
