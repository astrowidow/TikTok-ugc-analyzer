### 考え方

- 著者の枠組み（イノベーター → アーリーアダプター → アーリーマジョリティ → …）で、**界隈の構成が入れ替わるところ**で区切る。3〜5段階
- 各段階の名前は「イノベーター：海外のアニメファン」のように、段階名と誰が担ったかを30字まで。文にしない・かっこ書きを付けない（そのまま記事の見出しになる）
- 音源が2つ以上あれば（上の候補の「音源ごと」）、音源ごとに担い手・使い方・時期が違わないかを見る。曲の別の部分を切り抜いた音源で、
  あとから新しい使い方の波が起きていれば、それも段階の区切りと経路の下書きに書く（どの音源で・いつから・誰が・どう使ったか）。違いが無ければ音源には触れない
- 各段階の代表を2〜3本（seq）。「再生数順では落ちるが経路上は重要な動画」も挙げる
- 観測（表とラベルから言えること）と推測を分けて書く

### 出力の形（JSON 1つ）

```json
{"phases": [{"id": "P1", "name": "イノベーター：…", "start": "YYYY-MM-DD", "end": "YYYY-MM-DD",
             "summary": "何が起きたか（2〜4文）", "reps": [<seq>, <seq>]}, ...],
 "overlooked": [<再生数順では落ちるが経路上重要な seq>, ...],
 "pathway_md": "拡散経路の下書き（Markdown。段階ごとに観測と推測を分けて。seq を添える）"}
```

- id は P1 から順に。期間はすき間なく続け、最初の段階の start は {{first_date}} 以前、最後の段階の end は {{last_date}} 以降
- reps と overlooked の seq は、ラベルの付いた動画の中から
