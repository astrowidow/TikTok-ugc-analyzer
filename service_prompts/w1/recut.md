## 指示書（界隈の切り直し）

{{song}} のレポートを読んだ利用者から、**界隈（community）の分け方を変えたい**という指示が来た。
この仕事では、利用者の指示を十分に尊重して**分類軸を直す**。このあと、直した分類軸で動画のラベルを付け直し、レポートを新しい版に書き直す（次の仕事とサービスがやる）。

{{chapters}}

### 進め方

1. 指示が何を求めているかを決める: 界隈を分ける・まとめる・名前や定義を変える・新しい切り口（動機・年代・地域など）で切り直す・足す・消す。
   指示がレポートの本文の言葉（「2章の〇〇の人たち」など）で書かれていたら、read の `chapter:<id>` で該当箇所を読み、どの界隈のことかを当てる
2. 分け方を決める材料が要るなら読む: `labeled:<界隈の key>`（その界隈の動画。説明文・タグ・bio・サムネの場所・今のラベル）、サムネイルの一覧画像、
   `synthesis`（今の版の界隈ごとのコメント分析。界隈の中に別の動機の層が見つかっていることがある）。名前の付け方と粒度は `kb:community` にならう
3. 分類軸の全体を直して submit する。利用者に確認は取らない（指示どおりに進める。どう切り直したかは、最後に利用者へ伝わる）

### 決まり

- **利用者の指示を最優先する**。指示に無い界隈は、指示を通すのに要る範囲だけ動かす（定義の境目を直す・余った動画の行き先を決めるなど）。指示が手引きの粒度とずれていても、指示に従う
- 新しい界隈の定義には、後で別の AI がこの定義だけを見てラベルを付けられるよう、**見分けるシグナル**（bio の語・タグ・地域・サムネの特徴）を具体的に書く。分けた界隈どうしの境目は特にはっきり書く
- `keep` には、**定義を変えず、ほかの界隈から動画が移ってくることも無い**界隈だけを `{"前の key": "新しい key"}` で入れる（その界隈の動画は前のラベルのまま使い、付け直さない。key の付け替えもできる）。
  2つの界隈をそのまままとめるだけなら、両方を新しい key に向けてよい（`{"a": "ab", "b": "ab"}`）。分けた界隈・定義を変えた界隈・動画を受け取りうる界隈は入れない（付け直す）。迷ったら入れない
- format・motive・tier は、指示が求めていなければ変えない（変えると全部の動画を付け直すことになる）
- 地域はサービスが付けるので、軸に入れない

### 出力の形（JSON 1つだけ）

```json
{
  "taxonomy": {
    "community": {"<key>": "<定義と、見分けるシグナル（bio の語・タグ・地域・サムネの特徴）と例>", "...": "...", "unknown": "判断できない"},
    "format":    {"…": "今のまま（指示が求めたときだけ直す）"},
    "motive":    {"…": "今のまま"},
    "tier":      ["…今のまま…"],
    "examples":  {"<community の key>": [<その界隈の最初期の seq>, <代表的な seq>, ...]}
  },
  "keep": {"<前の界隈の key>": "<新しい界隈の key>"},
  "note_to_user": "どう切り直したか（1〜2文。利用者に伝える）"
}
```

- taxonomy は分類軸の**全体**（format・motive・tier も、今のものを写して入れる）
- 各軸に `unknown` を入れる。key は半角英小文字・数字・`_` だけ。community は 3 以上・20 まで
- `examples` は省いてよい（入れるなら、今ラベルの付いている動画の seq だけ）。`keep` が無ければ `{}`
